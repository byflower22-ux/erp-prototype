# ERP 公共版本标记组件

用于原型评审时标出某次迭代新增、优化和规则变化，业务模块只维护配置。实现为 `iteration-marks.js` 中的 `<erp-iteration-marks>` Web Component，无第三方依赖，可通过 `file://` 离线运行。参考 Revenue 的独立标记交互，在 ERP 内独立实现，不依赖或写入原项目。

## 使用方式

默认关闭区域标记，点击“显示标记”后展示目标虚线框及贴近原区域的编号；点击编号打开变更说明。沿用原来的边缘位置，仅在遮字或编号相撞时向附近空白处小幅偏移，不另设标记栏、不改变业务区或侧栏宽度。悬停或聚焦编号会加粗对应框。颜色对应新增（绿）、优化（橙）、规则（蓝）。“全部变更”始终可用，支持整个迭代／当前页面范围、页面定位和资料链接。

定位时按可见文字、输入控件及已放置编号做避让；小区域仅展示紧凑编号。搜索范围限定在原位置附近，极密集且没有空白的位置不强行叠放编号，对应说明仍可从“全部变更”查看。

工具栏显示当前页面配置项数，开启后另显示当前视口可见区域数。条件视图、屏幕外区域及没有选择器的规则不会产生可点击标记，但仍在清单内。标记表示评审范围，交付情况用说明单独表达。

## 可视化配置入口

统一工作台只保留顶部一条 **版本标记** 工具栏，页面与菜单共用显示开关、迭代筛选、全部变更、配置及导入导出。业务 iframe 只绘制编号，不再提供另一套入口。预算原型独立打开时保留原来的工具栏。

1. 左侧点击“新增标记”，或选择已有条目编辑；支持按标题、迭代和页面搜索。
2. 选择“标记范围”：**页面区域／菜单区域**。页面区域填写所属模块、页面；菜单区域默认归为公共菜单。填写所属迭代、类型、标题、说明和交付情况，可添加资料，纯规则可不选区域。
3. 点击“选择页面区域”，按所选范围在业务内容或一级／二级菜单移动鼠标预览、点击锁定；可选“上一级区域／返回下一级”调整范围，再点“使用此区域”。页面范围需先进入对应模块的目标页。点选期间拦截原按钮操作，Esc 取消并返回同一配置面板。选择器自动生成，也可手工维护；页面结构改变后需重新核对定位。
4. 点击“保存标记”后立即显示，并保存到当前浏览器；未保存切换条目或关闭时提示确认。顶部“管理迭代”支持新增、改名、删除，存在关联标记或只剩一个迭代时禁止删除。
5. “导出 JSON／导入配置”统一备份、转交与恢复菜单和页面配置；导入须为当前配置集，先校验再确认替换。“恢复项目配置”统一还原默认内容。浏览器禁止存储时仅本次预览有效，可通过导出保留。

调整序号：在配置面板左侧选中已保存标记，点击“↑ 上移／↓ 下移”。按全部标记顺序与相邻项交换，页面与菜单可互换位置；列表、区域编号和变更清单同步更新，排序立即保存，无需再点“保存标记”。当前表单尚未保存的文字会保留，需另行保存；新建未保存条目不可排序。首项不能上移，末项不能下移；搜索时按钮禁用，清空搜索后调整。导出 JSON／脚本保留排序，项目共享仍需更新配置文件；存储不可用时提示导出。

**本地保存不会写回项目文件。** 工作台共享配置导出脚本后更新 `原型/公共/version-marks-config.js`（全局名 `ERPVersionMarks`）；当前按用户确认导出发布 13 项（页面 10 项、菜单 3 项），详见[默认配置发布说明](../../文档/迭代/预算优化/版本标记项目默认配置.md)。预算独立页沿用本模块 `prototype/iteration-marks.js`，其导出脚本全局名为 `BudgetIterationMarks`，修改后构建 `_当前.html`。其他浏览器可导入 JSON 预览，本地自定义配置优先；接收新源码后可点“恢复项目配置”。

## 公共菜单标记

菜单是版本标记的一种范围，使用统一“显示标记／配置标记”。当前默认财务预算、申请、审批三项，与预算正文统一编号、筛选及查看说明；“当前页面”包含当前模块页面及公共菜单。点选一级、二级菜单时不展开／切换业务；正常菜单交互保留。折叠后子项编号隐藏，展开恢复；导航整体隐藏时不显示菜单编号。

初始菜单片段保留在 `menu-marks.js`；当前工作台以 `version-marks-config.js` 中完整发布配置为准，只保存统一配置集 `erp-version-marks`。首次打开时自动合并旧的 `budget-optimization` 与 `erp-navigation` 自定义内容及迭代，不删除旧存储；已存在统一配置时不再重复迁入。旧格式 JSON 先在旧独立页读取，统一界面接收统一配置集的 JSON。

编号继续贴近目标边缘，避字与避让方式不变，不增加独立栏、不改变侧栏宽度。`iteration-marks-bridge.js` 协调根页面与业务渲染器，以适配 `file://` 的 iframe 隔离；标记协议 `erp-iteration-marks-v1` 与页签协议分开，主端只接受登记 iframe 的消息，子端只接受父窗口。切换回单时公共入口保留，回单业务页不注入组件。

后续模块复用时：追加统一默认标记的 `scope:'page', module:'模块编号'`，在已登记业务 iframe 引入桥接脚本；业务首次渲染后以 `toolbar:false, storage:false` 配置组件，保留自己的 `root`、页面标识及导航函数，再调用 `ERPIterationBridge.renderer(element,'模块编号')`。同时在主端 `modules` 列表登记可选模块。菜单项使用 `scope:'menu', page:'navigation'`，无需模块 iframe。不得省略消息来源校验。

## 最小接入示例

```html
<erp-iteration-marks></erp-iteration-marks>
<main id="content" data-erp-page="overview"></main>
<script src="公共组件相对路径/iteration-marks.js"></script>
<script>
document.querySelector('erp-iteration-marks').configure({
  id: 'your-module',
  versions: [{id: 'ERP-I005', label: '本次迭代'}],
  marks: [{
    id: 'entry-change', version: 'ERP-I005', type: 'improved',
    page: 'overview', pageLabel: '业务概览', selector: '[data-change-entry]',
    title: '入口优化', description: '变化内容、业务规则和交互说明。',
    delivery: '原型可演示；正式接口待联调',
    documents: [{title: '需求说明', url: '文档/迭代/本次迭代/需求.md'}]
  }]
}, {
  root: document.querySelector('#content'),
  configGlobal: 'YourModuleIterationMarks', // 导出脚本赋值的全局名，与模块加载名称一致
  documentBase: new URL('ERP根目录相对路径/', location.href).href,
  navigate(page, mark) {
    // 使用模块已有导航函数；必要时依据 mark.id 切换月度／全年等条件视图。
    renderPage(page, mark);
  }
});
</script>
```

配置用普通脚本加载，不使用 `fetch` 读取本地 JSON，避免本地文件跨域限制。初始化需在业务区域首次渲染后调用；页面切换时同步 `root.dataset.erpPage`。渲染器观察区域重绘、尺寸及滚动变化，不包裹或改写业务 DOM。

## 配置约定

| 字段 | 说明 |
|---|---|
| `id` | 模块配置唯一编号；同一模块后续迭代保持稳定，不与其他模块共用 |
| `versions` | `{id,label}` 数组，迭代编号唯一；默认选最后一项。业务迭代编号与需求文档修订号分开 |
| `marks[].id` | 全配置唯一，建议稳定语义编号；显示序号按配置顺序生成 |
| `version` | 必须对应 `versions[].id`；后续迭代追加版本与标记，历史标记可保留 |
| `type` | `new` 新增、`improved` 优化、`rule` 规则 |
| `scope / module` | 工作台中 `scope` 为 `page` 或 `menu`；页面标记的 `module` 对应登记模块。独立组件可省略 |
| `page / pageLabel` | 模块页面标识／面向评审的页面名称 |
| `selector` | 相对 `root` 的 CSS 选择器，取第一个匹配元素；建议用稳定 `data-*` 属性。纯规则可省略 |
| `title / description` | 标题与说明，用纯文本展示；说明支持换行 |
| `delivery` | 区分原型可演示、需求规则、待联调等情况 |
| `documents` | `{title,url}` 数组；相对 `documentBase` 解析，支持 HTTP(S)，拒绝可执行协议和显式本地绝对地址 |

`configure(config, options)` 中 `root` 默认为页面 `main` 或 `body`；`getPage()` 可替代 `data-erp-page` 读取当前页；`navigate(page, mark)` 复用模块导航，需在下一动画帧前完成目标渲染。未提供导航函数时，跨页定位派发冒泡事件 `erp-mark-navigate`；定位不到目标派发 `erp-mark-unavailable`，并提示切换视图。`documentBase` 默认当前文档地址，推荐显式指定 ERP 根目录地址。

再次调用 `configure` 会先清理原观察器及编辑器，再载入配置。组件移出 DOM 时清理观察器和区域点选事件。无效配置展示错误说明；无效或暂不存在的选择器隔离跳过，不影响业务页面。保存编辑后派发 `erp-marks-change`，`detail.config` 为完整配置副本，供后续接入方对接自己的持久化能力；组件本身不请求服务端。

## 状态、导出与影响范围

- 显示开关及选中版本保存于 `erp-iteration-marks:<id>`，可视化配置保存于同键加 `:config`；不保存预算、单据或用户业务数据。浏览器禁用存储时仅本次预览生效，界面提示导出备份。
- 标记默认关闭，打印隐藏；Shadow DOM 隔离内部样式，说明抽屉使用原生 dialog，支持关闭按钮及 Esc。
- 独立 HTML 导出需将公共脚本及模块配置内联，并正确设置资料基址。预算构建器输出新文件，禁止覆盖迁入基线。
- 工作台由唯一公共入口管理统一配置；只有预算 iframe 已接入页面渲染器，回单业务页没有自动注入。新增模块按桥接接入步骤登记，检查菜单、页签、弹窗及跨模块状态。
