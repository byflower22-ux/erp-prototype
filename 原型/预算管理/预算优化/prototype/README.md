# 预算管理优化交互原型

日常使用 [ERP 统一工作台](../../../../index.html)；独立演示打开上级目录的“预算管理交互原型_当前.html”，无需安装或启动服务。无后缀 HTML 保留为迁入基线。原型使用虚构数据，不会连接或修改业务系统；查询及模拟审批主要保存在内存，刷新恢复，已保存调整草稿及版本标记偏好保存在当前浏览器。

2026-10-27 新增公共版本标记：演示条下方点击“显示标记”查看本轮区域变化，或点击“全部变更”阅读 13 项说明与需求／测试入口。业务配置为 `iteration-marks.js`，通用组件位于 `原型/公共/iteration-marks.js`，后续迭代按[公共规范](../../../公共/版本标记.md)复用。

同一工具栏右侧“配置标记”提供可视化新增／编辑／删除、管理迭代、点选区域、导入导出与恢复默认。保存到当前浏览器，不自动写回源码；项目共享时导出配置脚本（全局名 `BudgetIterationMarks`）更新本目录 `iteration-marks.js`，再重新构建。已有本地自定义内容优先加载，需用“恢复项目配置”读取最新默认内容。

正文编号贴近原区域，遮字或相撞时稍作偏移；不另设标记栏、不改变侧栏宽度。工作台顶部只保留统一“版本标记”入口，配置中选择页面／菜单范围，共用开关、版本、编号、清单和导入导出。嵌入模式隐藏本模块重复工具栏，通过公共桥接器绘制正文标记；独立页保留原入口及 13 项配置。

工作台配置导出脚本使用 `ERPVersionMarks`，更新公共 `version-marks-config.js`，包含正文与菜单。独立页仍使用本目录的 `BudgetIterationMarks`。旧正文与菜单浏览器自定义配置首次在工作台自动合并，之后以统一配置为准。

运行 `node build.cjs` 输出新的 `_当前.html`，包含公共标记与业务脚本；`--output` 可指定其他目标文件，禁止覆盖迁入基线。导出时只内存内联详情，不回写源文件；关联资料仍指向构建时的 ERP 根目录，完整资料评审推荐保留项目目录并使用统一工作台。

主要路径：

1. 首屏为团队预算执行：切换团队、预算归属月，查看四种管控方式及共享额度。月度和全年执行均不展示顶部统计卡片，筛选下方直接展示科目执行表。科目使用双栏级联选择器，悬停左侧一级或点击右箭头查看二级，点击圆点选择一级或二级，选择二级时同时展示所属一级；执行列表始终展开，无展开／收起操作。刷新旁不展示“示例”标签。月度统计及计算说明作为小副标题展示在“科目预算执行”右侧。执行页底部其余备注收进 ⓘ 提示：月度位于管控可用额度表头，全年位于全年科目执行标题旁，支持悬停或点击查看。
2. 点击管控可用金额打开计算说明，点击范围内实际／冻结继续查看对应范围明细。
3. 点击本月实际／冻结，只查看该月明细。
4. 实际明细支持人工导入／单据使用来源筛选，单据类型包含报销申请、付款申请、内部调账单、费用记账单、出差报销单、付款单、项目付款单、多项目付款单、固定资产付款单、报销单、项目报销单、多项目报销单、固定资产报销单、入企报销单。列表首列为“单号”，仅显示单号；不显示费用摘要，展示申请人“姓名（工号）”及单据标题。点击单号查看独立原单，点击“人工导入”来源查看批次追溯，不存在报销与付款关联。人工导入记录的申请人显示导入人“姓名（工号）”，查询和导出使用同一口径；缺少单号或单据标题时显示“—”。
5. 切换全年执行视图，展示财年预算、实际和当前有效冻结；各月分布支持预算／实际／冻结切换，实际和冻结均可下钻。冻结按预算归属月统计当前余额，不累加历史快照。
6. 财务预算概览保留原图1的工具栏、查询区及表格列，仅将每行“实际”入口改为“执行”；预算、预测及金额列保持原结构。“预算”和“执行”分别打开独立可关闭的工作页签，页面内不提供二者切换tab或返回概览按钮；通过顶部工作页签切换或关闭，切换时保留查询与编辑状态。“财务预算”也可关闭，关闭最后一个页签后展示工作区空态，可从左侧菜单重新打开。
7. 实际值导入入口位于“财务预算 → 批量操作 → 导入实际”，不设独立侧栏菜单；批量操作保留原有十个下拉项。
8. 预算编制允许调整示例预算，点击保存后重算执行额度；不修改真实系统。

顶部浅色工具条为原型演示区，不属于产品页面：

- 刷新失败：点击刷新查看失败提示，保留原取数时间；再次重试恢复。
- 空数据：查看空态，清空筛选或重置演示恢复。
- 无单据详情权限：触发后进入明细，点击单号或“人工导入”来源查看权限提示。
- 重置演示：恢复初始示例数据。

源文件：index.html、styles.css、model.js、approval.js、adjustment.js、application.js、iteration-marks.js、app.js。修改后运行 `node build.cjs` 重新生成当前独立文件。

现有系统实际确认节点、冻结状态覆盖、导入去重及权限配置仍需对接时核实。原型展示建议的交互口径，不代表已接入业务系统。

单据状态统一为：待审批、审批中、待财务审核、待支付、已支付、支付失败。冻结筛选包含全部状态，但仅展示当前有冻结的记录；示例已支付单据无剩余冻结，在实际单据详情中可查看。

明细列表和单据详情中的状态、来源类型使用普通文字，不使用彩色标签；列表状态列仅展示状态，不显示下方当前节点说明。人工导入文字仍支持点击追溯。

“预算管理”菜单默认展开，点击标题或箭头可展开／折叠“财务预算”“预算管控规则”，不关闭已打开的工作页签。

左侧在“预算管理”下方、“活动管理”上方增加“办公管理”，默认展开“申请”“审批”二级菜单，支持收起；“申请”展示团队预算调整申请入口；“审批”打开独立可关闭页签，按参考图复刻审批列表，默认搜索“预算调整”，展示团队预算调整申请单。支持审批分类、时间与属性筛选、搜索、详情、日志、同意、驳回、转审、加签、标签、内容展开、勾选及批量打印预览。所有操作为本地原型演示，不写入实际预算或真实审批系统。

预算管理与办公管理共用菜单样式和选中逻辑：一级按当前模块高亮，二级选中为左侧红色竖线、浅红背景和红色文字，悬停、缩进、圆角与展开／折叠效果一致。界面一致性要求已记入项目 AGENTS.md。

审批列表“详情”及标题打开预算调整审批详情独立页签。操作栏下不重复展示页面标题和单号。默认仅展示本次调整，不提供月份或方向筛选；调整原因仅在每项调整数据后展示，不设整体原因栏。完整预算始终展示全年，每个月份包含原始预算、调整前、调整后、变动金额和变动率，最后一列展示该科目本次调整原因并标明月份；保留历史调整与本次调整区别，支持定位到变更单元格；金额为纯文本，不提供点击查看原因。原始预算与调整前预算独立展示，变动以提交时调整前预算为基数。


“办公管理 → 申请 → 团队预算调整申请单”打开居中团队选择弹窗，选择2026财年和团队后打开独立可关闭的申请页签。同一团队重复打开复用页签。申请默认仅展示原型当前月2026-10，展开可编辑全年12个月，收起保留所有月份修改。每月展示原始预算、调整前、调整后、变动金额、变动率；二级科目调整后金额可编辑，一级科目自动汇总；最右侧为每个二级科目的原因输入，展开时固定在右侧。

草稿按团队保存到当前浏览器本地存储，重新打开可继续编辑；未保存关闭提供确认。提交要求至少一笔调整、非负金额且至多两位小数、变更科目原因完整。确认提交后在本地审批列表新增记录，审批详情读取提交时快照及原因，提交后的申请页只读。不修改真实预算或接入真实流程；刷新会重置本地模拟审批记录，已保存草稿仍可恢复。

预算执行使用唯一的可关闭工作页签，标题固定“预算执行”。页内切换团队或从概览点击其他团队的“执行”，均复用该页签并更新责任团队，保留所选月份、执行维度和科目筛选。

本期不提供新增在途报销、管控方式变更的自动变化检测及演示场景；用户通过手动刷新查询最新数据。

冻结明细与实际使用明细的单号统一打开当前系统内的“报销申请审批详情”可关闭页签，使用本地复刻的固定报销示例EXP-20260805-0048；取消或关闭返回来源明细，保留查询条件、分页和滚动位置。单号不再跳转其他项目或打开浏览器页面，人工导入来源追溯保持原样。

报销审批详情源文件为 reimbursement-detail.html、reimbursement-runtime.js、reimbursement.js。构建时将页面和脚本内嵌到独立原型HTML，无需自动审批项目文件；表单、发票、附件及审批记录支持切换，审批操作仅为本地示意。
