# 项目管理优化详细需求说明

> 迭代：ERP-I005｜版本：V1.0 按模块整理版｜更新日期：2026-11-24｜时区：Asia/Shanghai
> 读者：开发、测试、产品、财务和实施。本文定义正式建设要求，Demo用于交互参考，不代表生产接口和业务验收已完成。

项目分析的字段来源、公式、快照和累计取数集中在第5章；项目人效分析对应内容集中在第6章。阅读某一模块即可了解该模块的核算要求，无需另找共用核算章节。第7—8章只放共用文件交互、接口和运行约束，第9章保留验收场景，第10章列待落实事项。

本轮用户最新决议优先，确认历史及替代关系保留在[需求评审确认记录](需求评审确认记录.md)。本次是文档重组，不新增业务口径。旧结构已[归档](归档/详细需求说明_按主题版_2026-11-24.md)。

## 1. 范围与权限

### 1.1 菜单和本期边界

| 一级菜单／入口 | 二级菜单／页面 | 本期范围 |
|---|---|---|
| 订单管理 | 项目交付单 | 当前 Demo 订单管理下只展示此入口；列表、新增项目、项目详情与项目交付申请 |
| 项目管理 | 我的项目日程 | Web 工时查看、编辑、统计及当前人员操作日志；默认打开页签 |
| 项目管理 | 项目分析 | 项目概览、核算明细、项目核算数据导入、Excel 导出、AI 浮窗 |
| 项目管理 | 项目人效分析 | 人效分析概览、核算明细、人员奖金导入、Excel 导出、AI 浮窗 |
| 师资与教练管理 | 咨询师列表 | 关联 ERP 账号、固定人工默认配置、年度逐月固定人工维护；同时维护项目经理等非咨询师人员固定人工（Q20） |
| Demo 移动端入口 | 移动端首页→项目日程 | 首页中原“咨询”应用替换为“项目日程”；独立移动交互 |

- 默认打开“我的项目日程”，项目详情默认进入“项目交付”Tab。左侧菜单沿用统一的红色文字和左红线，不加浅红背景。
- 项目成员模块不编辑统一收入比例；指定团队在每次交付申请中填写本次成员收入分配。
- 不建设核算工作台、试算、手工月结、反结账、历史解锁／重发快照。退款本期只沿用既有信息展示，不新增核算联动。
- 日程无业务草稿、AI辅助、沿用上周／上月、单日补记；移动端仅本人，无日志、项目详情、多天批填或Web版本切换。
- 两分析模块不恢复优先关注事项、建议动作、预警规则、经营分层、利润变动归因、改善空间测算等已取消模块。
- 人效不按项目角色筛选；人员导入仅奖金，固定工资和社保公积金在咨询师列表维护。项目导入保留五类人工费用。

## 2. 我的项目日程

### 2.1 字段与保存校验

| 字段 | 规则 |
|---|---|
| 填报人员 | 关联 ERP 人员；本人固定姓名不可编辑；管理员 Web 点击弹窗选择单人，复用分析人员搜索组件 |
| 项目 | 仅可填所选人员具有有效成员关系的项目；显示项目名、项目编号、项目状态 |
| 项目角色 | 关联有效成员角色，作为记录身份；不是人效分析筛选项 |
| 工作日期 | 公司工作日；不允许休息日填报，调休按公司日历 |
| 工时 | 正数且为 0.5 小时倍数；清空或 0 按删除已有记录处理；不生成 0 小时事实 |
| 事项分类 | 每一条工时单独选择：项目准备、入企服务、后期复盘、其他 |
| 其他说明 | 仅分类等于“其他”时展示且必填；其他分类隐藏；建议最长 150 字（Demo 边界） |
| 记录 ID／版本 | 用于编辑、并发校验、日志前后值与来源追溯 |

- 同一天、同一项目可以有多条不同事项，例如准备 1h、入企服务 6h；不能用一个周级分类覆盖所有工时。
- 保存成功即正式生效，无审批，无业务草稿。“编辑中”只是未保存交互状态。
- 保存需统一校验该人员同日跨全部项目／角色≤8h、当月≤标准工时、同一事项重复及明确时间重叠。
- 编辑按“移除旧值＋应用新值”后的合计校验，不能把旧值新值重复相加。
- 不自动截断超额工时、不改为加班、不增设审批；保存失败保留当前输入并准确定位问题。
- 跨月周视图分别使用每月日历、时限和标准工时；不能用周中某一天月份约束整周。

### 2.2 Web填写和人员选择

 管理员在页面人员字段点击打开选择弹窗，复用项目分析的部门人员树和搜索控件。弹窗支持按姓名、工号、部门过滤，组织节点可展开／折叠，人员项显示姓名及工号，当前人员高亮；无匹配项展示空状态。选中单人后关闭弹窗，日程、工时统计及日志对象切换为该人员。不提供“全部人员”选项，不复用分析页面的筛选结果限制日程候选范围；候选仍须在日程管理员获授权范围内。

关闭或取消人员选择不改变原人员；切换遇到未保存工时时执行既有离开保护，取消切换保留原人员及输入。本人只显示固定姓名，无选择入口；移动端仍仅支持本人，不能通过账号参数或接口越权切换。项目分析与人效分析保留各自原有“全部人员”选项，不因共用控件而改变业务含义。


- 默认查看状态；进入“编辑工时／填写工时”后才出现编辑控件，提供“取消”“保存并退出”。
- 离开页面、切人员、切周月、关闭页签等有未保存修改时，弹窗只提供“保存并离开”“放弃修改”两种业务选择；点击遮罩／关闭不应静默丢失。
- 以按周填写为主，可切换按月；工时录入区与统计区用独立标题及容器分隔。
- 项目按“进行中→未开始→已结项→售后中→已关闭→未提交→已失效”排序；项目状态与项目交付单一致。
- 项目多于 3 个支持个人置顶；当前 Demo 为状态优先、同状态内按置顶顺序，跨状态置顶优先级见第10章D08。
- 项目列表一屏最多 4 个项目，超出区域纵向滚动，表头和合计可见。项目编号点击打开项目详情。
- 右侧刷新确实重新读取数据；未保存时先触发离开保护，不能刷新按钮无响应或静默丢输入。

### 2.3 工时统计

- 已保存统计来自正式工时；编辑时允许预览保存后结果，但须明确“含未保存工时”，未保存值不得进入核算。
- 统计随当前人员及本周／本月变化，至少提供项目工时、投入项目数、工作日覆盖及按项目／日分布，具体指标保留当前原型。
- 有效工时可汇总到人员月、项目月；不能把记录条数当小时或把项目成员数重复相乘。
- 个人项目工时利用率与日程填写完整率不是同一指标；零工时不自动判定缺勤。

### 2.4 操作日志

- Web 提供当前页面人员的日志，不能在日志弹窗内切换人员或查看全部人员。
- 不展示“操作角色”“日程人员”两列；展示操作时间、操作人、新增／修改／删除、日程日期／项目、修改前、修改后。
- 修改前后至少含工时、事项、其他说明；底层保留项目、人员、角色和版本，以便追溯。
- 默认最近一个月：例如 11 月 23 日查询 10 月 23 日 00:00 至 11 月 23 日 23:59:59.999；上月无同日时取上月最后一天。
- 按**操作时间**过滤，不是按日程日期；倒序排列；支持开始／结束日期、分页、10／20／50 条每页、跳页；查询改变回到第 1 页。
- 保存事务成功才产生正式日志；失败、取消不能伪造成功日志；移动端保存仍需后端记日志，仅不展示入口。

### 2.5 移动端交互

- 从移动首页“项目日程”进入；采用 ERP 现有移动页头与底部操作样式，不能直接缩小 Web 表格。
- 仅本人，可看周／月日期导航与统计，但每次填写具体某一天，不提供多天批量复制或填入。
- 默认一条输入：先选项目，再填工时、事项；底部“继续添加”创建下一条。
- 点击项目选择进入独立选择页，可搜索项目编号或名称，返回时保留未保存输入；项目编号只展示不可跳详情。
- 可用半小时步进及快捷小时选择，所有校验与 Web 相同。
- 查看／编辑状态明确，底部固定保存动作；离开保护使用移动端弹窗样式，只保留上述两个业务选择。

### 2.6 修改截止

成员本人从次月5日00:00起不能新增、修改或删除上月及更早月份的日程；按记录所属月判断，跨年同样生效。管理员在固化前不受5日限制，仍受工作日、单日8小时、月标准工时和审计校验。每月8日00:00固化上月后，所有核算相关输入锁定，管理员也不能改。时间由服务端北京时间判断。

## 3. 咨询师列表与固定人工

### 3.1 档案与ERP账号选择

- 列表展示姓名／工号、部门、联系方式、专业方向、入职日期、默认月固定工资、默认月社保公积金、核算周期、参与项目及维护操作；无角色、状态列、顶部统计、姓名图标或“分析”操作。
- 同时维护咨询师、项目经理等参与人员的固定人工，不因角色不同另建成本来源。一个ERP账号关联一份人员档案，同人多角色不重复创建。
- 新增及允许更换账号的编辑场景，点击“关联ERP账号”打开部门人员树弹窗，复用分析人员搜索样式；支持姓名、工号、部门及登录账号检索，无匹配时显示空状态，当前账号高亮，不提供“全部人员”。
- 已关联其他档案的账号置灰并标明原因；服务端保存时再次校验账号ID唯一性。已有项目或核算记录的人员保持原账号关联，不允许换绑。
- 选择后自动带出姓名、工号、状态、部门、入职日期、手机号、邮箱和ERP登录账号，均为只读。未选账号不能保存。
- 关闭、取消或Esc只退出账号选择，保留父表单。选择或更换账号也不清空已经填写的核算周期、成本、生效月份、专业方向及备注。

### 3.2 默认及月度固定人工

- 新增、编辑必填默认月固定工资及月固定社保公积金，允许明确填0，不能为负数。默认变更必须指定生效月份，保存有效版本；生效前仍取原配置，生效后未单独维护的月份取新默认。
- 月度固定成本弹窗按年份展示各月工资、社保公积金及合计，支持编辑；无金额来源列或恢复默认操作。具体月度人工金额优先于该月有效默认。
- 已手工维护的月度金额不被后续默认变更覆盖。无生效前默认时不倒用未来配置；已固化月金额和配置依据不回写。
- 上线首月、月中入职或离职月份，由授权人员人工维护当月金额，系统不按天数或工时再次折算。
- 离职次月起不再自动计入默认工资、社保及标准工时；离职前历史保留。离职后有效分配收入或补发奖金仍按所属月核算，不恢复默认人工。
- 固定人工只通过本模块维护，不接受人员奖金导入入口或旧固定人工模板写入。已固化月份及会改变已固化依据的默认变更均拒绝。

### 3.3 人工核算周期

- 新增、编辑提供开始月份和结束月份；开始必填且不早于入职月，结束可空表示长期，填写时不得早于开始，起止月均包含。
- 当月人效及人员候选不展示周期外人员；年累计仅汇总周期内月份，期间有适用月份的人员仍展示。年度收入矩阵周期外单元格为“-”。
- 人员奖金模板及月度固定成本表同样遵守周期。周期结束不删除档案或历史事实，不允许通过变更周期改写已发布快照；历史查询使用固化时的周期依据。

## 4. 项目交付单与收入分配

### 4.1 列表与新增

- 复用 ERP 项目交付单，保留既有列表检索、日期、项目状态及新增能力；本次不另建“项目列表”菜单。
- 列表可按项目编号、名称、订单编号检索，项目状态、团队等沿用 ERP 原筛选逻辑。
- 新增项目先关联订单，带出合同、客户、公司、项目金额等；产品所属团队、业务类型、项目名称、类型／子类型、销售、预计起止时间、成员等沿用当前 ERP 新增页面。
- 项目成员关系可维护人员与项目角色，不新增成员收入比例。
- 工时页、分析页与项目交付单读取同一项目状态字典。“筹备中”为 Demo 内部旧值，展示映射“未开始”；不得把内部旧值扩成新的业务状态。
- 所有页面项目名称下方展示项目编号，编号取正式 ERP 数据，不能用 Demo 拼接编号规则作生产编码规则。

### 4.2 交付列表

默认进入项目交付。列表依次包含：

| 顺序 | 字段 | 说明 |
|---|---|---|
| 1—4 | 序号、交付类型、交付审批单号、交付确认申请时间 | 类型为阶段确认／落地辅导，审批号可查看原单 |
| 5—8 | 项目模块、本次完成比例、本次交付金额、本次交付讲师 | 交付金额不能当作合同金额重复累计 |
| 9—10 | 交付确认完成时间、交付状态 | 审批完成才产生已确认收入 |
| 11 | 项目人员收入分配 | 位于备注说明前；有分配快照显示可点击“查看详情” |
| 12 | 备注说明 | 依原项目交付页面维护 |

没有配置的收入分配显示“-”且不可点击；不能仅因当前项目属于指定团队，就让没有历史分配记录的交付行显示可查看。

### 4.3 交付申请

- 阶段确认、落地辅导分别弹窗，使用项目基础信息及当前累计交付情况；阶段确认需要选择适用交付内容，落地辅导不重复展示该内容表。
- 本次交付比例与金额按合同额联动；本次金额必须大于 0，累计已交付＋审批中占用＋本次不能超过可交付金额。合同变更影响见 D05。

### 5.3 成本及利润计算

P为项目，U为人员，M为核算月份；以下I为项目当月确认交付收入，F为人员当月固定工资＋社保公积金，H为该人该项目正式工时，Hstd为该人整月标准工时。所有科目按核算所属月取数。

| 科目 | 取数／公式 | 影响个人核算 | 缺失语义 |
|---|---|---|---|
| 业务成本 | DS14 业务费用，按项目、费用所属月汇总 | 不直接作为个人费用 | 无记录是否为 0 需来源完整性标志，不能默认待补充 |
| 管理费 | DS14 项目管理实际费用 | 个人另按收入 20%计，不复用项目管理费 | 同上 |
| 交通差旅 | DS14 项目月人工导入值；本期唯一来源为人工导入 | 不再重复扣个人 | 应维护而未导入为待补充；明确导入0才是有效零，不能用ERP无流水推断0 |
| 税金（3.3%） | I(P,M)×3.3% | 个人税费按个人收入另算 | 收入未知则“-”，不是人工补充 |
| 大客户经理提成 | DS15 项目月费用 | 不自动计到某个人项目人员提成 | 人工输入缺失为待补充 |
| 项目交付提成 | 对项目成员DS12的适用期间提成X求和，按人员去重 | 同笔X计入对应个人；项目及个人均取同一人工录入金额 | 必要记录缺失为待补充；明确0有效，按各自依赖传播缺失 |
| 咨询师工资成本 | Σ[ F(U,M)÷Hstd(U,M)×H(U,P,M) ] | 个人计整月 F，不计此分摊数作为个人工资 | 工资或标准工时缺失且有投入时结果“-” |
| 项目异常费用 | DS15 项目月 exception | 不自动扣个人 | 待补充／已确认 0 |
| 年终奖分摊 | 当月项目确认交付收入 I(P,M)×4%，按分舍入；基础来源DS07及规则Q13 | 不自动形成个人奖金B，也不从B反算 | 收入已知0则为0；收入未知则“-”，不显示待补充，不要求人工填0 |
| 固定成本分摊 | DS15 项目月 fixed | 不自动扣个人 | 待补充／已确认 0 |

项目总成本为以上十项合计，不含项目所得税。项目管理费取ERP项目费用，不按个人20%管理费规则套算；个人奖金不自动计入项目，项目年终奖分摊单独按交付收入×4%计算。

```text
月税前利润 = 月确认交付收入 - 月总成本
累计税前利润 = 上线后至本月各月税前利润之和，跨财务年度不清零
累计所得税 = MAX(累计税前利润, 0) × 15%
月所得税 = 本月累计所得税 - 上月累计所得税
月净利润 = 月税前利润 - 月所得税
期间净利率 = 期间净利润合计 ÷ 期间确认交付收入合计
```

月所得税允许亏损回调为负；不承接上线前税基及税额。年度所得税为各月税额之和，不能按年度税前利润重新计15%。当月缺少必要依据时不输出完整成本、利润；累计按5.6的已有值政策汇总。收入≤0时利润率为“-”。

验算：首月税前利润10,000，所得税1,500；次月亏4,000，累计税前6,000，累计税900，次月税额－600，次月净利润－3,400。跨年度仍按此项目连续税基取月差。

### 5.4 盈亏平衡交付金额

```text
（交通差旅 + 大客户经理提成 + 项目交付提成 + 咨询师工资成本
 + 项目异常费用 + 年终奖分摊 + 固定成本分摊）
÷ [1 -（业务成本 + 管理费 + 税金）÷ 同期交付收入]
```

年终奖分摊先算收入×4%，以金额计入分子，分母不另扣4%，所得税不入公式。当月、年累计、项目累计分别用同范围已有费用及收入重算，不累加月度盈亏平衡值；收入≤0、分母≤0或当月必要依据未知时为“-”。例如收入100,000，业务成本6,700、管理费10,000、税金3,300，分子其他六项30,000，年终奖4,000，结果42,500。

| 人工分摊输入 | 参与人员、工资、社保、适用默认版本／月度覆盖、标准工时、工作日日历、正式工时及其版本、人员提成 |
| 其他成本输入 | 业务成本、管理费、交通差旅、大客户经理提成、异常费用、固定成本分摊原值及批次；年终奖4%与税金3.3%规则 |
| 月计算结果 | 十项成本、总成本、税前利润、项目累计税前利润、累计所得税、月税额、月净利润、盈亏平衡、工时和缺失标记；不只保存最终利润 |
| 追溯信息 | 月份、快照ID／版本、规则版本、输入指纹、任务ID、采集与发布时间、生成状态及校验结果 |

**读取规则。** 历史月份只读取该月已发布快照的输入、结果及历史维度，不能回退最新底账重算。历史无快照或没有该主体结果时，该月不贡献累计；单月明确快照尚未生成。当前月份读取实时有效输入，即使残留同月旧快照也不能覆盖实时结果。任务失败记录原因、告警并以固定截止输入重试，未成功不能冒充已结；重试不开放历史业务修改。

| 视图／字段类型 | 取数方法 |
|---|---|
| 当月 | 月份单选；历史月取本月快照，当前月取实时。仍展示项目累计回款、累计交付及期末应收，它们不是当月发生额 |
| 年累计 | 默认当前财务年度，仅选择年；当年2月至次年1月。当前年度截止当前月，历史完整年度截止次年1月末；收入、回款、科目成本、税额、利润、工时逐月求和 |
| 项目累计 | 无年或月选择，按项目汇总上线后至当前全部适用月，可跨财务年度；不重复期间回款／交付列，不按月拆行 |
| 项目金额、期末应收、状态及团队 | 取截止时点有效值／最后对应历史快照维度，不能把每月金额、余额或项目数量相加；新增以创建时间判断 |
| 累计回款与交付 | 上线后至统计截止的各月已有值合计，不因切换财务年度清零；不把历史快照中的累计列再次求和造成重复 |
| 净利率与盈亏平衡 | 用所选范围金额合计重新计算；不求和或平均月比例，不用最后一月代替累计 |

例：2026年11月查询年累计，取2—10月已发布快照＋11月实时；2027年1月仍属2026年度。各月交付10、20、30，累计交付柱依次10、30、60；期末项目金额／应收只取期末值。

**缺失与状态。** 当月人工应维护而未录入显示“待补充”，系统未知、依赖无法计算或不适用显示“-”；明确0是有效值。人工费用无发生也要录0，留空不改已有值。概览只提示缺失数量，明细列缺项。完整当月显示“实时核算”或“已结快照”，不完整当月显示“数据缺失”，快照发布状态与业务完整性独立。

年累计和项目累计按已有输入及月结果统计，不提示缺失，不剔除有已有结果的项目，不展示“已知合计”或缺失星号；不向底账或快照写0。累计明细及Excel同时隐藏数据状态、缺失内容和对应筛选，忽略遗留状态筛选；仍保存底层来源和缺失标记。缺少当月数据不阻断其他已有值，分母≤0或不适用指标仍为“-”。

### 6.3 人员成本与利润

U为人员，M为核算月份；IU为个人交付收入，F为固定人工，XU为跨项目提成合计，A为单笔交付的个人分配金额。

```text
人员交付收入 IU(U,M) = Σ该人员在 M 月博商咨询管理项目已确认交付的分配金额 A
固定人工 F(U,M) = 月固定工资 + 月固定社保公积金
提成 XU(U,M) = Σ所有项目的人员应计提成 X(U,P,M)
税费 = IU × 3.3%
管理费 = IU × 20%
个人总成本 = 固定人工 + 提成 + 奖金 + 税费 + 管理费
个人税前利润 = IU - 个人总成本
个人所得税 = MAX(个人税前利润,0) × 15%
个人净利润 = 个人税前利润 - 个人所得税
个人净利润率 = 个人净利润 ÷ IU
当月盈亏平衡交付收入 = (固定人工 + 提成 + 奖金) ÷ [1 - (税费 + 管理费) ÷ IU]
```

个人所得税逐月分别计算，亏损月不向其他月份回调；年度税额和净利润直接求和各月结果，不能按年度税前利润再算15%。固定人工计人员整月金额，不能用分摊到项目的工资反作个人工资。人员奖金只计个人，不自动再计项目成本；项目年终奖另按项目交付收入×4%算。

当月盈亏平衡仅当月展示，使用本月已录入的固定人工、提成和奖金，分母中税费及管理费按本月金额占交付收入计算。收入≤0、分母≤0或当月必要依据缺失时为“-”。年累计不展示该字段。

验算：收入50,000、工资10,000、社保2,000、提成5,000、奖金1,000；税费1,650、管理费10,000，总成本29,650，税前20,350，所得税3,052.50，净利17,297.50，净利率34.595%，盈亏平衡23,468.06。

### 6.4 工时及人工分摊

| 指标 | 公式及来源 | 特别说明 |
|---|---|---|
| 项目投入工时 | Σ人员所选期间上线后已保存的正式项目工时 | 不计未保存编辑值、不重复统计多角色同记录 |
| 考勤标准工时 | Σ所选期间在职适用月份的 DS05 整月标准工时；上线首月仍取整月，离职次月起不再计入 | 不是截至今天已过工作日工时，也不是上线后剩余工作日工时 |

| 小时产出 | 人员交付收入÷项目投入工时 | 零工时无法算，不显示无穷大 |
| 人工投入产出比 | 人员交付收入÷（固定人工＋提成＋奖金） | 与净利率不同；分母未知或≤0时“-” |

项目分摊人工＝月固定人工÷整月标准工时×该项目投入工时。例：固定人工12,000、标准160h，甲40h、乙60h，则甲分摊3,000、乙4,500，个人成本仍12,000，未分摊4,500，利用率62.5%，未投入60h。未分摊人工留在个人成本，不强分给项目；未投入工时不等于可排班产能。利用率及其他比例用总分子÷总分母，不平均月或个人百分比。

## 7. 共用导入与AI交互

### 7.1 文件导入流程

1. 下载区和上传区分开，导入弹窗不展示模板预填多少条数据。
2. 下拉筛选点击外部空白区域关闭，多选不应误关；切月份、筛选后清空旧预览并要求匹配新范围模板。

5. 不通过 Excel 公式缓存值绕过校验；金额列只接受非负确定数字。
6. **人工费用无发生已确认：** 对应维护的人工费用及人员奖金，没有发生也需明确导入0；从未录入该业务键时为缺失、显示“待补充”，不能自动按0核算。已有金额时，空白＝保持原值；0＝覆盖为0；非空＝设值覆盖，不做金额累加。没有原值时留空仍为缺失，不能转换为已确认0。
7. 预览展示数据类型、项目／人员、原金额、新金额、错误；全部预览成功且存在已填金额才允许确认。
8. 只上传和预览不写入。确认前重新检查权限、月份、数据版本、模板匹配和全部业务规则。
9. 整个文件作为一个原子事务：任何一行失败不允许前面成功后面失败；重复确认返回原成功结果，不重复入账。
10. 记录来源文件、文件校验信息、模板／批次 ID、确认人、前后值和时间；导入后刷新当前分析。
11. 生产建议按受影响记录版本检测冲突，而不是无关操作导致全系统模板失效；当前 Demo 使用全底账指纹。采用哪种冲突粒度需接口评审。
12. 已固化月份按Q11禁止导入；预览及确认两次检查锁定。预览后才固化的文件也不能确认写入；不得通过改月份、旧模板或AI入口绕开。

- 个人收入来源应能解释“哪笔交付、多少金额、分配多少比例、何时确认”。
- 金额变更可说明原值、新值和修改人；不能只有一句“系统计算”。

- 核算明细不恢复已删除操作列；来源入口可由现有诊断／AI来源及授权业务单据承接。

## 8. 开发数据与运行约束

### 8.1 基础字段约束

- 所有金额以人民币元为核算单位，展示保留两位小数；万元图表只做显示换算，不改底账。
- 金额、比例采用定点十进制计算；正式实现避免二进制浮点的累计误差。工时按 0.5 小时，分配比例按百分比最多两位小数。
- 金额保存到分，单笔分配、单人单项目月人工分摊按分舍入；项目合计和个人合计由底层舍入后明细汇总。跨对象舍入尾差单独保留，不隐性补给某人，规则见 D11。
- 记录必须区分：业务日期、核算所属月份、创建／修改时间、实际写入时间、快照生成时间。不能用最近更新时间替代核算月份。
- 业务主键必须稳定；项目编号、工号用于展示与检索，不因人员改名生成新账。
- 零值表示已确认 0；未填写／未知为 null 或缺记录，两者必须区分。
- 业务事实由 ERP 产生，AI 只解释；不得把 AI 输出当作未校验的财务金额。

### 8.4 异常返回

建议用稳定错误码与中文信息区分：NO_PERMISSION、OUT_OF_SCOPE、PERIOD_MEMBER_LOCKED、SNAPSHOT_LOCKED、VERSION_CONFLICT、NON_WORKDAY、DAILY_HOURS_EXCEEDED、MONTHLY_HOURS_EXCEEDED、ALLOCATION_OVER_100、MISSING_SOURCE、TEMPLATE_EXPIRED、FILE_INVALID、DUPLICATE_KEY、IMPORT_PREVIEW_EXPIRED。

错误信息应指明人员／项目、月份／日期、问题字段和恢复动作；不输出工资等越权详情。正式错误码名称可跟随ERP规范，但测试需要能够区分上述场景。

### 8.5 一致性与运行约束

- 前后端统一精度、统一计算层；前端展示计算仅做预览，服务端结果为准。
- 导入与工时保存防重复点击、超时重试；网络返回失败不能直接再次累加。
- 快照运行、业务写入、导出并行时采用版本隔离；已确认预览原数据变化应作冲突。
- 自动任务需监控最近成功月份、失败次数、缺失数量和对账结果；补偿后不伪造按时完成。
- 历史月数据不能被前端本地缓存版本覆盖；浏览器刷新读最新有效数据／授权快照。
- 文件上传、模板下载、AI文件处理共用附件权限和病毒／格式校验能力，按ERP现有安全策略实施。
- 事务日志、人员成本、快照保留期限及性能量化目标未确认，列D09；不擅自承诺“永久保留”或某秒级响应。

### 9.5 财务对账与上线

- 抽取至少一组项目上线后累计、跨年度所得税回调、人员跨项目分摊及两笔交付分配样本，由财务独立核对原始事实、公式和输出。
- 按“项目收入→交付明细→人员分配＋未分配”及“人员固定人工→各项目分摊＋未分摊”进行对账；个人成本总和不要求等于项目成本总和，两者包含科目不同。
- 不仅验最终利润，还核对每个科目、标准工时、累计税基、来源批次、快照输入集合与维度时点。
- 核对原型交互、接口鉴权、导入原子性、失败重试、固定截止的失败补偿及固化后全量锁定，不以单元测试代替这些业务验收。
- 上线前须关闭影响金额、历史锁定及权限的阻塞项；未关闭项不得以“Demo已有”豁免。
