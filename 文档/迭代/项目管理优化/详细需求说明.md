## 2. 我的项目日程

### 2.1 字段与保存校验

| 字段 | 规则 |
| --- | --- |
| 填报人员 | 关联 ERP 人员；本人固定姓名不可编辑；授权人员 Web 点击弹窗选择单人 |
| 项目 | 仅可填所选人员具有有效成员关系的项目（在ERP项目交付单中的项目）；显示项目名、项目编号、项目状态 |
| 项目角色 | 关联有效成员角色，作为记录身份；不是人效分析筛选项 |
| 工作日期 | 公司工作日；不允许休息日填报，调休按ERP日历 |
| 工时 | 正数且为 0.5 小时倍数；清空或 0 按删除已有记录处理；不生成 0 小时事实 |
| 事项分类 | 每一条工时单独选择：项目准备、入企服务、后期复盘、其他 |
| 其他说明 | 仅分类等于“其他”时展示且必填；其他分类隐藏；最长 150 字 |

• 同一天、同一项目可以有多条不同事项，例如准备 1h、入企服务 6h；不能用一个周级分类覆盖所有工时。

• 保存成功即正式生效，无审批，无业务草稿。“编辑中”只是未保存交互状态。

• 保存需统一校验该人员同日跨全部项目／角色≤8h、当月≤标准工时、同一事项重复及明确时间重叠。

• 编辑按“移除旧值＋应用新值”后的合计校验，不能把旧值新值重复相加。

• 不自动截断超额工时、不改为加班、不增设审批；保存失败保留当前输入并准确定位问题。

• 跨月周视图分别使用每月日历、时限和标准工时；不能用周中某一天月份约束整周。

### 2.2 Web填写和人员选择

 管理员在页面人员字段点击打开选择弹窗，复用项目分析的部门人员树和搜索控件。弹窗支持按姓名、工号、部门过滤，组织节点可展开／折叠，人员项显示姓名及工号，当前人员高亮；无匹配项展示空状态。选中单人后关闭弹窗，日程、工时统计及日志对象切换为该人员。不提供“全部人员”选项，不复用分析页面的筛选结果限制日程候选范围；候选仍须在日程管理员获授权范围内。

关闭或取消人员选择不改变原人员；切换遇到未保存工时时执行既有离开保护，取消切换保留原人员及输入。本人只显示固定姓名，无选择入口；移动端仍仅支持本人，不能通过账号参数或接口越权切换。项目分析与人效分析保留各自原有“全部人员”选项，不因共用控件而改变业务含义。

• 默认查看状态；进入“编辑工时／填写工时”后才出现编辑控件，提供“取消”“保存并退出”。

• 离开页面、切人员、切周月、关闭页签等有未保存修改时，弹窗只提供“保存并离开”“放弃修改”两种业务选择；点击遮罩／关闭不应静默丢失。

• 以按周填写为主，可切换按月；工时录入区与统计区用独立标题及容器分隔。

• 项目按“进行中→未开始→已结项→售后中→已关闭→未提交→已失效”排序；项目状态与项目交付单一致。

• 项目多于 3 个支持个人置顶，demo例子周知行；当前 Demo 为状态优先、同状态内按置顶顺序。

• 项目列表一屏最多 4 个项目，超出区域纵向滚动，表头和合计可见。项目编号点击打开项目详情。

• 右侧刷新确实重新读取数据；未保存时先触发离开保护，不能刷新按钮无响应或静默丢输入。

### 2.3 工时统计

• 已保存统计来自正式工时；编辑时允许预览保存后结果，但须明确“含未保存工时”，未保存值不得进入核算。

• 统计随当前人员及本周／本月变化，展示工时卡片、项目投入及工作事项投入。Web和移动端均不展示“周工时趋势”；Web保留两栏投入统计，移动端上下排列。

• 有效工时可汇总到人员月、项目月；不能把记录条数当小时或把项目成员数重复相乘。

• 个人项目工时利用率与日程填写完整率不是同一指标；零工时不自动判定缺勤。

### 2.4 操作日志

• Web 提供当前页面人员的日志，不能在日志弹窗内切换人员或查看全部人员。

• 展示操作时间、操作人、新增／修改／删除、日程日期／项目、修改前、修改后。

• 修改前后至少含工时、事项、其他说明；底层保留项目、人员、角色和版本，以便追溯。

• 默认最近一个月：例如 11 月 23 日查询 10 月 23 日 00:00 至 11 月 23 日 23:59:59.999；上月无同日时取上月最后一天。

• 按操作时间过滤，不是按日程日期；倒序排列；支持开始／结束日期、分页、10／20／50 条每页、跳页；查询改变回到第 1 页。

• 保存事务成功才产生正式日志；失败、取消不能伪造成功日志；移动端保存仍需后端记日志，仅不展示入口。

### 2.5 移动端交互

• 从移动首页“项目日程”进入；采用 ERP 现有移动页头与底部操作样式，不能直接缩小 Web 表格。

• 仅本人，可看周／月日期导航与统计，但每次填写具体某一天，不提供多天批量复制或填入。

• 默认一条输入：先选项目，再填工时、事项；底部“继续添加”创建下一条。

• 点击项目选择进入独立选择页，可搜索项目编号或名称，返回时保留未保存输入；项目编号只展示不可跳详情。

• 可用半小时步进及快捷小时选择，所有校验与 Web 相同。

• 查看／编辑状态明确，底部固定保存动作；离开保护使用移动端弹窗样式，只保留上述两个业务选择。

### 2.6 修改截止

成员本人从次月5日00:00起不能新增、修改或删除上月及更早月份的日程；按记录所属月判断，跨年同样生效。管理员在固化前不受5日限制，仍受工作日、单日8小时、月标准工时和审计校验。每月8日00:00固化上月后，所有核算相关输入锁定，管理员也不能改。

## 3. 咨询师列表与固定人工

### 3.1 档案与ERP账号选择

• 列表展示姓名／工号、部门、联系方式、专业方向、入职日期、默认月固定工资、默认月社保公积金、核算周期、参与项目及维护操作；

• 同时维护咨询师、项目经理等参与人员的固定人工，不因角色不同另建成本来源。一个ERP账号关联一份人员档案，同人多角色不重复创建。

• 新增及允许更换账号的编辑场景，点击“关联ERP账号”打开部门人员树弹窗，复用分析人员搜索样式；支持姓名、工号、部门及登录账号检索，无匹配时显示空状态，当前账号高亮，不提供“全部人员”。

• 已关联其他档案的账号置灰并标明原因；服务端保存时再次校验账号ID唯一性。已有项目或核算记录的人员保持原账号关联，不允许换绑。

• 选择后自动带出姓名、工号、状态、部门、入职日期、手机号、邮箱和ERP登录账号，均为只读。未选账号不能保存。

• 关闭、取消或Esc只退出账号选择，保留父表单。选择或更换账号也不清空已经填写的核算周期、成本、生效月份、专业方向及备注。

### 3.2 默认及月度固定人工

• 新增、编辑必填默认月固定工资及月固定社保公积金，允许明确填0，不能为负数。默认变更必须指定生效月份，保存有效版本；生效前仍取原配置，生效月及以后未固化月份按新工资和社保配置覆盖，包括已单独修改的月度值及之后已排定的默认版本。

• 月度固定成本弹窗按年份展示各月工资、社保公积金及合计，支持编辑；无金额来源列或恢复默认操作。可单独修改某月金额；后续编辑默认人工时，生效月及以后仍由新配置覆盖。

• 已手工维护的月度金额在后续默认变更生效月及以后也会被覆盖，生效前金额不变。覆盖前值和后续版本记录审计；之后仍可单独编辑未固化月份。已固化月不可改，涉及固化期间的生效月份保存失败，不静默部分覆盖。

• 上线首月、月中入职或离职月份，由授权人员人工维护当月金额，系统不按天数或工时再次折算。

• 离职次月起不再自动计入默认工资、社保及标准工时；离职前历史保留。离职后有效分配收入或补发奖金仍按所属月核算，不恢复默认人工。

• 固定人工只通过本模块维护，不接受人员核算数据导入入口或旧固定人工模板写入。已固化月份及会改变已固化依据的默认变更均拒绝。

### 3.3 人工核算周期

• 新增、编辑提供开始月份和结束月份；开始必填，最早2025年1月，且不能早于ERP入职月份，两个下限同时满足。结束可空表示长期，填写时不得早于开始，起止月均包含。

• 当月人效及人员候选不展示周期外人员；年累计仅汇总周期内月份，期间有适用月份的人员仍展示。年度收入矩阵周期外单元格为“-”。

• 人员奖金／其他成本模板及月度固定成本表同样遵守周期。周期结束不删除档案或历史事实，不允许通过变更周期改写已发布快照；历史查询使用固化时的周期依据。

## 4. 项目交付单与收入分配

### 4.1 列表与新增

• 复ERP 项目交付单，保留既有列表检索、日期、项目状态及新增能力；本次不另建“项目列表”菜单。

• 列表可按项目编号、名称、订单编号检索，项目状态、团队等沿用 ERP 原筛选逻辑。

• 新增项目先关联订单，带出合同、客户、公司、项目金额等；产品所属团队、业务类型、项目名称、类型／子类型、销售、预计起止时间、成员等沿用当前 ERP 新增页面。

• 项目成员关系可维护人员与项目角色，不新增成员收入比例。

• 工时页、分析页与项目交付单读取同一项目状态字典。“筹备中”为 Demo 内部旧值，展示映射“未开始”；不得把内部旧值扩成新的业务状态。

• 所有页面项目名称下方展示项目编号，编号取正式 ERP 数据，不能用 Demo 拼接编号规则作生产编码规则。

### 4.2 交付列表

现有订单管理-项目交付单中的阶段确认、落地辅导分别弹窗中，判断项目数据博商咨询项目时（使用之前判断是博商咨询主体的编码变）新增填写成员收入配置：

### 本次交付的人员收入分配

| 项目 | 规则 |
| --- | --- |
| 显示条件 | 产品所属主体＝博商咨询管理，两个申请均在附件模块上方展示；仅该团队产生人员分配收入；不新增“交付团队”作为判断字段 |
| 成员来源 | 当前项目成员；同人多角色合并一行，角色合并展示；姓名、工号、部门自动带出 |
| 必填内容 | 每位成员本次收入分配比例，未参与分配明确填 0 |
| 单人校验 | 0—100%，最多两位小数 |
| 总量校验 | 全体成员合计允许低于 100%，不得超过 100%；全 0 属于允许范围 |
| 金额 | 单人成员收入＝本次确认交付金额×本次比例，按分舍入 |
| 剩余比例 | 未分配部分仍属于项目交付收入，不强行补齐到某个人 |
| 保存内容 | 申请保存成员、比例、金额与身份快照；确认后形成分配事实，不随成员变更而丢失 |
| 展示入口 | 项目交付列表“项目人员收入分配”查看本次分配，不是查看全项目统一月比例 |

• 整条审批通过后才形成项目收入及个人分配收入，统一计入审批通过时间所属的北京时间自然月。服务月、申请月、回调接收月都不能替代审批通过月。

• 每笔交付保存成员、身份、比例及金额事实，后续成员变化不重写原分配；重复回调只入一次。已通过交付不允许撤销或冲减，异常撤销消息不得删账或生成反向收入。

## 5. 项目分析

本模块以“一个项目”为核算对象，查看项目收入、回款、成本和利润。页面分为“项目概览”和“核算明细”两个Tab，两处使用相同的项目范围。先选择查看期间，再计算期间发生额；项目金额、应收和项目状态另取统计截止时点的值。

### 5.1 页面与筛选

| 控件 | 选择方式及作用 |
|---|---|
| 统计方式 | 当月、年累计、项目累计；三种方式的时间范围见5.2 |
| 核算期间 | 当月选择月份；年累计只选择年度；项目累计不选择年或月 |
| 项目团队 | 点击弹窗选择单个团队或全部团队 |
| 项目搜索 | 表格上方选择项目名称、项目编号、订单编号或项目类型，再输入关键字 |
| 项目经理 | 点击人员树弹窗，按姓名、工号或部门搜索，可选择全部人员 |
| 项目状态 | 仅在核算明细表头多选；选项与项目交付单一致：进行中、未开始、已结项、售后中、已关闭、未提交、已失效 |
| 数据状态 | 仅当月核算明细提供表头筛选；年累计、项目累计隐藏该字段及筛选 |

团队、项目搜索和项目经理同时作用于概览、明细及导出。表头项目状态／数据状态只过滤明细行，不改变概览范围；切到累计时忽略遗留的数据状态条件。筛选弹层点击外部空白关闭。

负责人不单设筛选；项目顾问不搜索、不筛选、不排序。金额、日期、工时等可排序字段在表头切换升序、降序、取消；项目名称、编号、订单编号、类型及各人员／团队／状态字段不作排序。顶部不堆叠期间口径说明，必要说明放悬停提示。

### 5.2 统计期间与取数顺序

**先确定项目范围。** 取授权范围内、统计截止时已存在且符合筛选的项目。已结项、已关闭或本月没有收入的项目不会因此被自动排除。“当月新增项目”再按项目真实创建日期筛选，不用预计开始日期替代。

| 统计方式 | 统计哪段时间 | 如何得到结果 |
|---|---|---|
| 当月 | 所选自然月；当前月截止查询时点 | 取该月收入、回款、成本、利润及工时；同时保留项目累计回款、累计交付及期末应收 |
| 年累计 | 当年2月1日至次年1月31日；当前年度截止当前月 | 将该财务年度内各月已有发生额相加；不另选截止月份 |
| 项目累计 | 功能上线后至当前查询时点，可跨财务年度 | 将该项目全部适用月份的已有发生额相加；无年、月选择，不按月拆行 |

年度例子：2026年度为2026年2月至2027年1月。当前为2026年11月时，年累计只计2—11月；2027年1月仍属2026年度。仅系统统计的业务事实从上线后开始；人工导入金额按其填写月份直接使用，不自动做首月折算。上线前已有项目及其基础资料仍可展示。

**再按月份选择数据版本。** 当前月份读实时数据；历史月份读已发布月快照。历史没有快照或没有该项目结果时，该月不参与累计，不从当前底账回算历史；单月查询说明快照尚未生成。当前月即使残留旧快照，也必须读实时数据。

| 数据类型 | 累计时的处理 | 例子 |
|---|---|---|
| 发生额 | 各月已有值相加 | 回款、交付、各成本科目、所得税、净利润、工时 |
| 时点值 | 取统计截止时点的一份值，不按月相加 | 项目金额、期末应收、项目状态、团队、经理及成员关系；历史截止取对应快照 |
| 项目累计回款／累计交付 | 上线后至统计截止的月发生额相加，跨年不清零 | 不把每月快照中已累计过的数再次相加 |
| 比率及盈亏平衡 | 用相同范围的金额合计重新计算 | 净利率＝净利润合计÷交付收入合计；不平均月利润率 |

例如：9月、10月快照交付分别10万、20万，11月实时交付30万，三月累计交付60万。若项目金额100万，9—11月分别回款5万、10万、15万且此前无回款，11月期末应收为70万；不能把三个月的应收余额相加。累计只按已有值统计，不提示数据缺失，具体缺失显示见5.7。

### 5.5 利润和盈亏平衡公式

其他成本分别按“项目＋月份”和“人员＋月份”独立维护，互不自动分摊或重复计账；两者均为成本，影响各自总成本、税前利润、所得税及净利润。原有盈亏平衡公式保持本节七项分子及三项费用占比，不自动把新增其他成本计入盈亏平衡或人工投入产出比分母。

**项目所得税逐月计算，税基跨年度延续。**

1. 月税前利润＝月确认交付收入－月总成本。
2. 截至本月累计税前利润＝上线后各月税前利润之和；不承接上线前利润或税额。
3. 截至本月累计所得税＝累计税前利润与0取较大值，再乘15%。
4. 本月所得税＝本月累计所得税－上月累计所得税，允许负数回调。
5. 本月净利润＝本月税前利润－本月所得税。

例：首月税前利润10,000，税额1,500，净利润8,500；次月亏4,000，累计税前利润6,000、累计税900，次月税额为－600，次月净利润－3,400。两月税额合计900，净利润合计5,100；跨财务年度也不把税基清零。

**盈亏平衡金额按所选期间计算。**

分子＝交通差旅＋大客户经理提成＋项目交付提成＋咨询师工资成本＋项目异常费用＋年终奖分摊＋固定成本分摊。

分母＝1－（业务成本＋管理费＋税金）÷同期确认交付收入。

盈亏平衡交付金额＝分子÷分母。年终奖分摊先按收入×4%算后放分子，分母不另扣4%；所得税不计入公式。收入≤0、分母≤0或当月必要值未知时显示“-”。净利率同样在收入≤0时为“-”。

例：收入100,000，业务成本6,700、管理费10,000、税金3,300，分子中除年终奖外合计30,000；年终奖4,000，结果＝34,000÷（1－20,000÷100,000）＝42,500。

### 5.6 项目月快照

每月8日北京时间00:00开始生成上月快照，取截至该时点已保存且归属上月的有效数据，正常补录到7日结束。即使有缺项也照常保存已有值和缺失标记；固化后工时、固定人工、提成、费用及核算依据全部锁定，管理员也不能补改删，不提供解锁或重发。

快照分别记录业务期末、采集截止、任务开始、完成及发布时间。月末有效项目金额和余额不能用次月8日的最新值代替。生成失败需记录、告警并按同一固定截止输入重试；未发布不能显示已结，也不能借重试修改历史。

| 必须固化的数据 | 具体内容及用途 |
|---|---|
| 项目身份与维度 | 项目ID、名称、编号、订单编号、状态、类型、团队、负责人、项目经理、顾问、成员角色和有效关系、创建与预计起止日期；用于历史列表及筛选 |
| 期末金额和事件 | 月末项目金额、累计回款、累计交付、应收结果及对应输入；延期、中止、退费使用的事件日期、金额与状态 |
| 收入和回款依据 | 原交付／回款业务ID、单号、金额、业务日期、审批通过时间、所属月、有效状态及来源版本；保留分配关联 |
| 工资分摊依据 | 各人的工资、社保、月度覆盖或默认生效版本、整月日历及标准工时、正式项目工时、人员提成和分摊结果 |
| 费用依据与结果 | 业务成本、管理费、差旅、大客户经理提成、异常费用、固定成本分摊、项目其他成本及导入批次；税金3.3%、年终奖4%的规则与结果 |
| 核算结果及版本 | 十一项成本、总成本、月及累计税前利润、累计与月所得税、月净利润、盈亏平衡、工时、缺失标记；月份、快照ID、规则／输入版本、任务及校验结果 |

新增其他成本纳入月快照的原金额、所属月、主体、导入批次、费用结果及完整性标记。新增前已固化的旧快照不补写该科目，也不因新字段重新判历史缺失；累计按旧快照已有值汇总。

历史查询、累计、来源核对和导出必须使用同一月快照版本。后续调薪、部门变更或成员调整只影响其有效期间，不回写旧快照；不能只保存最终净利润而丢失其计算依据。

## 6. 项目人效分析

本模块以“一个人员”为核算对象，查看交付收入、个人成本、利润和工时利用情况。项目收入依据每笔交付的成员分配计入个人；个人固定人工按整月配置计入，项目端则按工时分摊这份人工。两者使用不同的工资口径，不能互相替代。

### 6.1 页面与人员范围

当月核算明细“数据状态”在表头提供多选筛选，复用项目分析图标和浮层：实时核算、已结快照、数据缺失；有筛选／重置，点击空白关闭，不排序。条件仅过滤明细及导出，不影响概览，与项目分析分别保存。年累计不显示状态列及筛选，并忽略残留状态条件。

不提供项目角色筛选，不默认仅看咨询师；项目经理等人员使用同一算法、同一咨询师列表固定人工配置。姓名、工号、部门不排序；金额、数量、日期、工时等字段在表头升序、降序、取消，未知值后置。

| 人员情况 | 是否计入本模块 |
|---|---|
| 在授权范围且当月在人工核算周期内 | 当月展示；没有项目不自动排除 |
| 入职前、周期外或功能上线前 | 对应月份不核算、不计缺失；年度矩阵显示“-” |

| 离职次月及以后 | 不自动计默认工资、社保及标准工时；有有效分配收入或补发奖金时，按所属月计入原人员，不恢复默认人工 |

### 6.2 当月和年累计如何取数

| 统计方式 | 时间范围 | 数据版本与汇总方法 |
|---|---|---|
| 当月 | 所选自然月，当前月到查询时点 | 历史月读已发布人员快照，当前月读实时；周期外人员不展示 |
| 年累计 | 当年2月至次年1月，当前年度到当前月；只选年 | 按适用核算月份逐月读取历史快照＋当前月实时，将已有收入、工资、社保、提成、奖金、其他成本、成本、税额、利润及工时相加 |
| 年度比率 | 与年度金额使用同一人员和月份范围 | 净利率用合计净利÷合计收入；利用率用合计项目工时÷合计标准工时；小时产出及投入产出比同样重算，不平均月百分比 |

例：2026年11月查2026年累计，读取周期内2—10月已发布快照及11月实时；2027年1月仍属于2026年度。历史无快照或没有该人员结果时，该月不贡献累计，不以当前工资或分配数据倒算；当前月残留旧快照也不能覆盖实时值。

系统收入和工时只统计上线后适用事实，原有账号和人员主数据继续复用。人工成本金额由授权人决定，按其所属月直接使用，不自动按首月、天数或工时比例折算。

### 6.5 利润和工时计算示例

**个人利润逐月计算。**

1. 固定人工＝当月固定工资＋当月社保公积金。
2. 总成本＝固定人工＋提成＋奖金＋其他成本＋交付收入×3.3%＋交付收入×20%。
3. 税前利润＝交付收入－总成本。
4. 所得税＝税前利润与0取较大值，再乘15%；每月独立计算。
5. 净利润＝税前利润－所得税；净利润率＝净利润÷交付收入。

例（其他成本为0）：收入50,000，工资10,000、社保2,000、提成5,000、奖金1,000；税费1,650、管理费10,000，总成本29,650，税前利润20,350，所得税3,052.50，净利润17,297.50，净利率34.595%。年累计直接加各月税额及利润，亏损月不抵回其他月份。

**盈亏平衡交付收入**＝（同期固定人工＋同期提成＋同期奖金）÷［1－（同期税费＋同期管理费）÷同期交付收入］。当月用当月金额；年累计用所选财务年度内适用月份的已有金额合计重新计算，字段名为“年度盈亏平衡交付收入”，不相加或平均月度盈亏平衡值。上述例子为18,000÷［1－11,650÷50,000］＝23,468.06。收入≤0、分母≤0或当月必要依据未知时为“-”；年累计沿用已有值统计，除数不可算仍为“-”。零收入仍可有成本及亏损，不因除法无法计算就自动判整行缺失。

**项目人工分摊与个人固定人工分别计算。** 同一人固定人工12,000、标准工时160小时，在甲项目40小时、乙项目60小时：甲分摊3,000，乙分摊4,500，个人仍计固定人工12,000，未分摊人工4,500；项目工时100小时，利用率62.5%，交付天数12.5、上班天数20、未投入工时60小时。

各人的项目分摊＝月固定人工÷整月标准工时×该项目工时。未分摊人工留在个人成本，不强行分给项目；未投入工时可能包含请假、内部工作或漏填，不能直接当作空闲产能。小时产出＝交付收入÷项目工时；人工投入产出比＝交付收入÷（固定人工＋提成＋奖金）；分母≤0为“-”。

**交付收入不按工时分摊。** 同月第一笔交付20,000，甲60%得12,000、乙30%得6,000；第二笔10,000，甲20%得2,000、乙50%得5,000。甲合计14,000、乙11,000，未分配5,000仍属于项目收入；不能用30,000乘最后一笔比例代替逐笔计算。

### 6.6 人员月快照

每月8日北京时间00:00生成上月人员快照，固定截至该时点已保存的上月有效数据；缺奖金或工资也照常生成，保留缺失标记，不补0。固化后工资、社保、奖金、提成、工时、分配及核算依据全部锁定，管理员不能改；以后改默认工资不回写历史。

| 必须固化的数据 | 具体内容及用途 |
|---|---|
| 人员身份与适用范围 | 人员ID、姓名、工号、部门、入离职日期、人工核算周期、参与项目、角色和有效关系；用于历史范围及筛选 |
| 逐笔收入依据 | 交付ID、项目、确认交付金额、个人比例与分配金额、审批通过时间、所属月和来源版本；保留未分配部分 |
| 成本依据 | 月工资、社保公积金、月度覆盖或有效默认版本、各项目人员提成、个人奖金、人员其他成本及导入批次 |
| 工时与分摊依据 | 适用考勤日历、整月标准工时、正式工时的项目／日期／事项／角色及版本、各项目人工分摊、未分摊人工 |
| 月核算结果 | 个人收入、各成本、总成本、税前利润、所得税、净利润、盈亏平衡、各工时指标和缺失标记 |
| 版本与任务 | 所属月份、快照ID、规则与输入版本、输入指纹、采集截止、任务开始／完成／发布时间、状态及校验结果 |

人员其他成本同样保存月金额、来源批次、成本利润结果及缺失标记；新增前已固化快照保持原版本，不补写其他成本或回写历史利润。

历史查询、年度汇总和导出均读取该月同一已发布快照，不能用当前工资、部门或分配覆盖历史。任务失败记录及告警，以同一截止输入重试；未发布不显示已结，不因此允许修改历史或改成当前月入账。当前月份始终用实时有效数据，累计读取顺序见6.2。

### 6.7 零值缺失与数据状态

当月需要人工维护的奖金、其他成本、提成或固定人工没有有效值时显示“待补充”；系统来源未知、依赖无法计算或不适用时显示“-”；明确0是有效值。人工金额空白不代表0，奖金和其他成本无发生也须明确导入0。费用缺失只阻断依赖它的利润等指标，已有分配收入和工时仍可展示。

当月概览只统计缺失人数，提示到明细查看；明细列具体缺项。完整当前月为“实时核算”，完整历史快照为“已结快照”，必要值缺失为“数据缺失”。快照发布成功与输入完整是两回事；当月0收入但成本齐全不是数据缺失。

年累计用已有值统计，保留有已有结果的人员，排行、月趋势和收入矩阵不展示缺失数量、待补充、缺失星号或已知合计标签；明细及导出隐藏数据状态和缺失内容，保留年度盈亏平衡交付收入。年度来源可以由历史快照与当前实时组成，但不显示状态列，也不增加隐藏状态筛选。底层缺失及快照锁定规则保留，分母为0的比率仍为“-”。

### 6.8 人员核算数据导入与明细导出

**导入。** “导入数据”弹窗标题为“人员核算数据导入”，支持“奖金、其他成本”两种费用类型，多选或全部；下载模板和上传数据分区，不展示模板条数。所属月份单选，部门多选／全部，无角色筛选；候选受部门、人工核算周期及权限约束。一个Sheet，一人一月一行。

模板前五列固定为：序号、工号、人员姓名、部门、所属月份；之后按所选类型追加“原金额、录入金额”成对列。仅奖金时为原奖金（元）、奖金录入（元），Sheet名“人员奖金”；仅其他成本时为原其他成本（元）、其他成本录入（元）；选择全部时先奖金后其他成本，Sheet名“人员核算数据”。仅录入列可改，无工资、社保或固定人工列，旧工资模板不能写入本入口。

金额按人工填写值计所属月，不自动折算；空白不改已有值、0明确覆盖、非空设值覆盖，不重复累加。上传先预览，确认后才保存；复核身份、月份、金额、模板及数据版本、权限、人工核算周期和固化锁定。任何行失败全文件不写入，重复确认不重复计账，保存导入批次及前后值。

人员其他成本计该人总成本及利润，不自动计入项目、不改固定工资或社保。例：人员原税前利润20,350、所得税3,052.50、净利润17,297.50；当月导入其他成本500后，税前19,850、所得税2,977.50、净利润16,872.50。奖金和其他成本分别设值，选择单一类型不会清空另一类型。

**导出。** 导出当前部门／人员、期间及排序下全部匹配人员，不只可见行；从概览导出仍用相同范围核算明细。字段顺序与6.4一致，当月31列、年累计29列，一人一行。数据版本与查询固定一致，0、待补充和“-”依当前视图原义输出。
