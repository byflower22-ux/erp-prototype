# 项目与人员核算建设计划

版本：2026-11-06 整理版  
状态：业务与交付计划，供评审及开发拆解；本文未实施ERP改造或创建小龙虾Skill。

## 1. 建设目标

在自研ERP基础上，建设通用项目工时、收入成本数据、月结及核算看板。本期实现咨询师核算，后续其他角色复用基础能力并增加角色规则。

优先满足五个目标：

| 目标 | 落实方式 |
|---|---|
| 轻量化 | 复用ERP账户、项目、数据、技术栈和部署环境；财务模板生成及导入放在小龙虾，不另建对应ERP上传页面 |
| 通用性 | 人员、项目、角色、科目、所属期间采用通用模型；基础工时记录不写死咨询师 |
| AI化 | 小龙虾处理日程/聊天材料理解、模板拼装、导入编排、数据问题说明及指标查询 |
| 准确性 | 正式数据保存在ERP；程序校验和计算；统一来源、幂等导入、修改留痕、月结快照 |
| 便捷性 | App/Web均支持项目日程；截图和文字生成可编辑草稿；财务只填预填模板中的数值 |

## 2. 最新方案与范围

### 2.1 已确认的建设边界

1. 使用现有自研ERP，可开发接口；不建设独立业务系统。
2. 项目日程及工时录入同时支持ERP移动App和Web。
3. 项目与咨询师分析看板仅建设在ERP Web。
4. 工时按天、项目和角色记录；无需项目负责人或财务审批。
5. 本期不设置加班分类及单独加班统计。
6. 日程采用截图识别；聊天采用截图和粘贴文字识别。本期不接企微日程及会话读取接口。
7. 月固定人工成本、项目人员提成、项目人员奖金、项目异常费用、项目固定成本分摊，通过小龙虾Skill生成预填模板并导入。
8. 模板先由Skill调用ERP接口获取项目、人员、时间等信息，用户下载后只填数值，再上传给小龙虾。
9. 工时、成本等基础功能通用；本期只实施咨询师核算规则。
10. 项目恢复月度明细，金额由月度累加形成项目累计；合同总金额独立展示。
11. 项目利润使用确认交付收入，不使用合同额作为收入基数。
12. 财务月结后锁定，反结账后方可调整历史数据并重新核算。

### 2.2 工具分工

| 工具 | 正式职责 | 使用边界 |
|---|---|---|
| ERP | 项目及业务数据、正式工时、财务导入数据、校验、计算、权限、月结和Web看板 | 正式业务数据源和核算结果归属处 |
| 小龙虾 | 材料理解、模板生成、文件接收、导入预览与编排、核算异常解释和问数 | 通过接口操作，不能绕过ERP校验及月结 |
| 企微 | 用户原有日程和聊天材料来源 | 本期只通过用户主动上传截图或粘贴文字使用内容 |
| WorkBuddy | 开发协助、历史文件整理和一次性迁移辅助 | 不作为日常核算链路的必需依赖 |

## 3. 总体架构

```text
ERP App                         ERP Web
项目日程、AI辅助填写             项目日程、财务查询/月结、核算看板
       └────────────────┬────────────────┘
                        ↓
                 ERP通用核算接口
       身份、权限、版本、幂等、校验、追溯
                        ↓
                 ERP核算数据与程序
       工时、收入成本明细、角色规则、月结快照
                        ↑
              ERP现有项目及业务数据

小龙虾
  ├─ 工时辅助：截图/文字 → 结构化草稿 → 本人确认 → 工时接口
  ├─ 导入Skill：查询ERP → 输出模板 → 接收填写文件
  │                           → 预校验 → 用户确认 → 批量写入
  └─ 分析辅助：调用统一指标接口 → 解释结果并链接来源
```

优先在现有ERP应用内增加模块。是否需要独立文件存储或任务执行组件，按现有能力选择；不预设新增微服务、消息队列或另一个业务数据库。

## 5. 通用项目日程与工时

### 5.1 日程操作

- 按人员、项目、项目角色、日期记录工时。
- 支持选择时间段、拖动调整、按小时填写、复制某天/某周和跨日批量安排。
- 使用起止时间时按有效时段计算小时数；仅知道日期和小时数时，允许直接填写，不虚构起止时间。
- 人员由登录身份带出，项目优先显示本人参与的项目，角色从成员关系带出。
- 同一人具有多个角色时，同一段投入不能重复归集。
- 工作说明选填，非项目时间不强制填报。
- 工时每日拆分，可按周批量确认提交。
- 计划、复制内容、AI生成内容先进入草稿；本人确认提交后作为实际投入。
- 无审批环节。财务月结检查不等同于工时审批。

### 5.2 AI辅助填写

输入支持多张日程截图、多张聊天截图、粘贴聊天文字及混合材料。

```text
上传/粘贴
→ 识别日期、项目、人员、角色、工作内容、起止时间/小时数
→ 查询ERP项目及成员候选
→ 处理疑问、检查重复及冲突
→ 展示按天排列的可编辑草稿
→ 本人一次确认提交
```

识别与确认规则：

| 场景 | 处理 |
|---|---|
| 日程仅代表计划 | 提示确认实际发生与实际时长 |
| 全天日程 | 不直接认定8小时 |
| 聊天缺少时长 | 留空待补，不按聊天消息跨度推算 |
| 相对日期 | 按可靠的原始日期解释；没有可靠日期则询问 |
| 其他人员的工作 | 不自动归到上传者名下 |
| 同一事项多来源出现 | 提示合并，避免重复累计 |
| 不同材料互相矛盾 | 展示冲突，不静默选择一个值 |
| 图片模糊、字段缺失 | 定位疑问，只要求补充不确定项 |
| 跨日时间段 | 拆到各日期并供确认 |

截图和聊天文字属于待识别材料，其中的指令性内容不能成为工具执行授权；AI只提取本功能所需的工时事实。

### 5.3 状态、校验及锁定

状态为草稿、已提交、已锁定；材料解析另设处理中、成功、失败状态。

- 草稿不计入核算；提交后直接生效。
- 未结月份可修改或删除，保存修改记录并更新核算。
- 已结月份只读；反结账后可调整。
- 校验必填、小时数、日期、成员权限、重复和时间重叠。
- 每天标准8小时，每月标准工作天数取ERP考勤日历。超额及非工作日投入标记异常，不自动截断或转成加班；最终拦截边界在上线前配置。
- App和Web共享记录及版本，更新时防止覆盖另一端的新修改。

## 6. 小龙虾“核算数据模板导入Skill”

### 6.1 设计原则

模板在小龙虾中生成，用户在本地填写数值后重新上传。ERP无需单独开发五类模板生成与上传页面。

Skill是统一入口，按数据类型选择字段及校验规则；模板生成、读取及数值校验由固定程序执行，避免大模型对金额自由转写。

### 6.2 五类模板

| 类型 | 由ERP预填 | 用户填写 | 说明 |
|---|---|---|---|
| 月固定人工成本 | 人员ID/姓名、角色、月份 | 月固定人工成本金额 | 一人一月一条，不能按每个项目重复导入；包含工资及公司承担的社保公积金等 |
| 项目人员提成 | 项目ID/名称、人员ID/姓名、角色、归属月份 | 提成金额 | 作为项目和人员核算的共同来源 |
| 项目人员奖金 | 人员ID/姓名、归属月份及适用项目 | 奖金金额 | 与项目年终奖分摊分别维护；项目归属是否改变费用映射见第15节 |
| 项目异常费用 | 项目ID/名称、分配月份、预计费用口径 | 当月预计金额 | 各月金额汇总形成当前项目预计总额 |
| 项目固定成本分摊 | 项目ID/名称、分配月份、预计费用口径 | 当月预计分摊金额 | 各月金额汇总形成当前项目预计总额 |

时间、项目和人员不适用的维度不强行铺设。例如月人工模板不按项目重复展开，项目异常费用不要求指定人员。

### 6.3 第一阶段：输出模板

1. 用户向小龙虾提出数据类型和月份范围，例如“生成2026年11月的咨询师提成模板”。
2. Skill只补问缺少的范围信息；项目、人员范围可按ERP返回候选选择。
3. 调用ERP查询适用项目、人员、角色、成员关系、月结状态及已有数据版本。
4. 生成Excel模板，输出下载文件。
5. 项目、人员、月份等预填列锁定；金额列突出显示，单位固定为元。
6. 模板携带模板类型、版本、批次、行标识和项目/人员ID。服务器保留对应生成批次，导入时核对身份及行范围，不能仅信任文件中的ID。
7. 首版建议金额列留空，已有金额以只读参考列展示，避免误覆盖。

缺少成员或月份时，先调整范围重新生成模板。不得依赖用户自行改名称、插入无标识行来建立新关系。

### 6.4 第二阶段：上传与写入

1. 用户上传填写后的模板。
2. 固定程序读取工作表和金额，校验模板版本、行标识、数据类型及数值格式。
3. 调用ERP预校验，核对授权、归属、金额重复、数据版本及月结锁定。
4. 小龙虾输出预览：新增、更新、未填写、异常记录数量和明细；更新显示原值、新值和差额。
5. 用户确认本批次和确定的预览版本。
6. 调用批量写入接口。服务器再次校验，避免预览后被其他人修改而仍覆盖写入。
7. 返回导入批次、成功/失败结果及异常文件或清单。

### 6.5 统一导入语义

- 空白表示本次不处理，不清零已有金额。
- 数字0表示明确设置为0。
- 金额按“将该记录设置为此值”处理，不因再次上传而追加累计。
- 月份、项目、人员由模板身份定位，不做模糊写入。
- 相同提交重试不得重复入账；文件内容变化后作为新预览处理。
- 含公式的金额单元格不直接作为最终金额，要求转为确定数值后导入。
- 已结月份不得直接覆盖，需反结账后重新预校验。
- 推荐按预览中明确选定的有效记录整体事务写入；异常记录不在本次确认范围内。若正式提交时校验失败，整批选定记录不写入，避免部分成功不清楚。
- 保存文件、生成批次、预览、确认人、操作时间和写入结果。
- 回退受权限与月结控制，不直接删除已被结算的历史记录。

| 数据 | 来源及方式 |
|---|---|
| 项目、订单、合同金额、成员、角色 | ERP已有数据，项目订单一对一 |
| 确认交付收入 | ERP已有人工确认数据，保留所属月份 |
| 回款及应收 | ERP已有记录和既有口径，不将应收简单写死为合同减回款 |
| 业务成本、差旅、管理费 | ERP实际费用，已有项目及费用所属月份 |
| 人员、入职时间 | ERP人员信息 |
| 标准工作天数 | ERP公司考勤日历，含节假日和调休 |
| 收入分配比例 | 财务维护，按月份生效并保留版本；本期不自动纳入五类导入模板 |
| 大客户经理提成预计总额、项目年终奖预计分摊 | 财务维护，并补充月度归属；本期不擅自扩入已指定的五类Skill模板 |

收入比例同项目同月合计允许低于100%，不得超过100%；未分配部分为公司或团队保留收入。

人工项目预计费用按月归集。对于总额先确定的费用，可用月度分配草稿协助维护；自动分配的默认方法需确定后才固化。

## 8. 项目核算规则

### 8.1 核算周期与收入

- 项目按月形成明细，各月金额累加形成项目累计。
- 合同总金额保持独立总额，不按月拆分、不作为利润收入。
- 月收入取ERP当月确认交付收入。
- 累计回款、累计交付收入、合同额分别展示。

### 8.2 成本项目

| 项目成本项 | 当月取数规则 | 口径 |
|---|---|---|
| 业务成本 | ERP费用所属月份 | 实际 |
| 管理费 | ERP费用所属月份 | 实际 |
| 交通差旅 | ERP费用所属月份 | 实际 |
| 税金 | 当月确认交付收入×3.3% | 核算公式 |
| 大客户经理提成 | 项目预计金额的当月分配 | 预计 |
| 项目交付提成 | 该项目人员提成按归属月份汇总 | 财务指定金额 |
| 咨询师工资成本 | 月人工成本按当月项目工时分摊 | 实际归集 |
| 项目异常费用 | 当月预计金额 | 预计 |
| 年终奖分摊 | 项目预计金额的当月分配 | 预计 |
| 固定成本分摊 | 当月预计分摊金额 | 预计 |

项目“咨询师工资成本”只含固定人工分摊，提成单独计入“项目交付提成”。

项目人员奖金与个人月度奖金的具体项目成本映射须在开发前确定，不得擅自同时计入项目年终奖分摊造成重复。

### 8.3 利润

```text
月总成本＝各成本项合计
月税前利润＝当月确认交付收入－月总成本
月净利润＝月税前利润－月所得税

累计收入/成本/税前利润/所得税/净利润＝各月对应金额之和
月净利率＝月净利润÷月交付收入
累计净利率＝累计净利润÷累计交付收入
```

所得税税率15%，亏损时为0。项目跨月盈亏抵扣尚需确认：

- 方案一：各月正利润×15%，累计税额为各月合计，不跨月抵扣。
- 方案二：按累计利润测算税额，再用本月累计税额减上月累计税额得到月度税额，可能产生税额回调。

这是财务规则决策，不将其中一种表述为已确认结果；确定后两张看板及所有查询统一使用。

### 8.4 项目盈亏平衡回款

```text
盈亏平衡回款
＝（交通差旅＋大客户经理提成＋项目交付提成
   ＋咨询师工资成本＋项目异常费用
   ＋年终奖分摊＋固定成本分摊）
 ÷［1－（业务成本＋管理费＋税金）÷累计交付收入］
```

成本取项目累计金额。累计收入为0时显示“无法测算”；分母小于或等于0时显示“当前费用结构下无法达到盈亏平衡”。所得税不参与此公式。

该指标反映保持当前费用占比下的测算，不是已经收到的回款。项目累计结果重新计算该指标，不累加各月盈亏平衡值。

## 9. 咨询师月度核算规则

### 9.1 收入与工时

```text
个人当月交付收入
＝Σ（项目当月确认交付收入×本人在该项目当月有效收入比例）

月标准工时＝考勤日历标准工作天数×8
当月交付天数＝当月全部已提交项目工时÷8
项目饱和度＝当月全部已提交项目工时÷月标准工时
```

项目工时包含交付、方案准备、资料分析、项目内部沟通和项目差旅等全部项目相关时间。

### 9.2 固定人工与分摊

```text
个人月固定人工成本
＝固定工资＋公司承担的社保、公积金等用工成本

个人分摊到项目的当月人工
＝个人月固定人工成本÷月标准工时×该项目当月工时
```

人员月度核算计入整月固定人工；未投入项目的人工保留在个人成本中，不强行分摊给项目。提成、奖金不包含在固定人工中。

### 9.3 费用与利润

```text
税费＝个人当月交付收入×3.3%
管理费＝个人当月交付收入×20%
总成本＝税费＋整月固定人工＋当月提成＋当月奖金＋管理费
税前利润＝个人当月交付收入－总成本
所得税＝MAX（税前利润，0）×15%
净利润＝税前利润－所得税
净利率＝净利润÷个人当月交付收入
```

提成按项目、人员及归属月份取数。咨询师奖金与项目年终奖预计分摊分别维护。

### 9.4 个人盈亏平衡点

```text
盈亏平衡点
＝整月固定人工
 ÷［1－（税费＋提成＋管理费＋奖金）÷个人当月交付收入］
```

沿用现有表格公式。交付收入为0时“无法测算”；分母小于或等于0时“当前费用结构下无法达到盈亏平衡”，不以0或负数冒充测算结果。

业务对象不等于必须一对象一物理表；按ERP现有规范实施。正式数据统一以ERP为准。

### 11.2 规则通用化边界

- 科目名称、归属维度、适用角色、简单费率及生效期间可配置。

- 不开发任意公式编辑器、通用工作流引擎或全角色利润规则。
- 同一份人员工资和工时只有一份来源；分摊是派生结果，不能重复作为新增原始成本。
- 同一人同月跨角色的工资如何归属，在其他角色接入前明确，不默认每个角色各计一遍全月工资。

| 接口组 | 主要能力 |

## 12. 月结、准确性和权限

### 12.1 月结

```text
汇总本月业务及录入数据
→ 检查工资/比例/标准工时等缺失和异常
→ 固定程序试算
→ 财务查看结果并月结
→ 保存输入依据、规则和结果，锁定期间
```

未结数据可以重算。已结月份源数据发生变化时生成差异，不能悄悄覆盖旧结果。反结账记录操作人、原因和时间；如影响后续依赖月份，提示影响范围并按统一规则重算。

### 12.2 准确性

- 金额使用精确小数，统一舍入及尾差分配，月度和累计按同一结果汇总。
- 来源单据、导入批次和工时记录具备稳定标识，防止重试和重复导入。
- 预计与实际分别标识，同类实际费用以后接入时必须确定替换/差额规则，防止双计。
- AI只组织事实和操作建议，正式金额与公式由固定程序解析和计算。
- 隐藏ID和Excel列保护仅辅助防错，服务器仍核对模板批次、行范围、权限和数据版本。
- 保存记录修订版本，任何看板金额可追溯到来源。

### 12.3 权限

| 角色 | 权限 |
|---|---|
| 普通项目人员 | 维护本人日程及工时，不查看核算明细 |
| 项目负责人 | 可按授权查看项目投入；不承担工时审批 |
| 人事/财务 | 按授权生成、导入人工成本模板及查看相关记录 |
| 财务 | 比例与费用维护、导入、试算、月结、反结账及核算查看 |
| 授权管理人员 | 查看授权范围内的核算看板和明细 |

工资文件和个人利润不在公共群传播；材料下载与AI数据访问受同一业务权限约束。

### 14.1 关键验收场景

1. Skill能查询指定范围并输出预填项目/人员/月份的Excel，用户仅填金额即可导入。
2. 空白与0语义正确，重复上传不重复累计，原值/新值/差额可核对。
3. 预览后数据被另一人修改时，提交检测冲突，不静默覆盖。
4. 模板身份字段被篡改、权限不符、已结月份等由服务器拒绝。
5. 日程、聊天截图和文字可生成多天多项目草稿，模糊项明确待补，不猜测时长。
6. 工时提交直接生效，无审批；App和Web同步，重复/重叠可发现。
7. 工时未填满时不强行分完月工资；咨询师核算仍计整月人工。
8. 项目人工与人员提成可追溯，跨视图共用来源且不重复归集。
9. 项目月度金额累加等于累计，合同额不被按月重复相加；比例指标重新计算。
10. 两类盈亏平衡公式、零分母及亏损所得税符合确认口径。
11. 月结锁定与反结账生效，源数据变化有差异提示。
12. 采用财务认可的样本与原Excel逐项对算，包含多项目、比例变更、闲置时间、跨月提成、亏损及预计费用调整。
13. 普通咨询师无法查看工资、核算明细和他人导入材料。
14. AI查询与看板同一筛选范围返回相同数值，并可追溯来源。
