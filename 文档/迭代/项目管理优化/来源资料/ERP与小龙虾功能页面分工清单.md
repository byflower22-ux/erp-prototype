# ERP与小龙虾功能页面分工清单

版本：2026-11-06  
依据：《项目与人员核算建设计划》及当前已确认要求。以下为拟开发范围，不代表功能已实现。

## 一、总体分工

| 承担方 | 主要职责 | 用户入口 |
|---|---|---|
| ERP | 正式数据、日程、校验、固定公式计算、月结、权限和看板 | 现有App与Web |
| 小龙虾 | 截图文字理解、预填模板生成、文件接收、导入编排、结果解释 | 小龙虾现有对话；ERP日程调用其解析能力 |
| 用户 | 确认实际投入、填写模板数值、确认财务导入及月结 | 对应业务入口 |

工时提交即生效，无审批；AI生成内容须本人确认。模板由小龙虾输出，填写后上传回小龙虾；ERP不重复建设五类模板的下载/上传页面。

### ERP页面结构

```text
ERP App
└─ 项目日程
   ├─ 我的日程
   └─ AI辅助填写/草稿确认（页面内）

ERP Web
├─ 项目日程
│  └─ 我的日程＋AI辅助填写
├─ 项目详情（原页面）
│  └─ 核算设置（新增页签）
├─ 财务工作台
│  ├─ 核算数据
│  ├─ 导入记录
│  └─ 月结
└─ 核算分析
   ├─ 项目分析
   └─ 咨询师分析
```

ERP Web按四个主要工作界面组织：项目日程、财务工作台、项目分析、咨询师分析；另扩展项目详情的核算设置页签。标签、弹层、抽屉不必各做成独立菜单。

## 三、小龙虾功能及交互清单

| 编号 | 功能 | 实现内容 | 用户交互/输出 | 是否另建页面 |
|---|---|---|---|---|
| L01 | 工时材料理解 | 理解日程截图、聊天截图及文字；提取日期、项目、工作内容和明确时长；匹配ERP候选 | ERP项目日程内上传/粘贴，返回结构化草稿与疑问 | 否，复用E02 |
| L02 | 工时批量调整 | 理解“周一到周三每天下午甲项目3小时”等指令，整理修改建议；调用ERP检查重复和冲突 | 日程AI入口中展示修改后的草稿，本人确认提交 | 否，复用E02 |
| L03 | 导入模板生成Skill | 理解类型及范围，调用ERP获取项目、人员、角色、月份和已有金额，拼装五类Excel模板 | 小龙虾对话中输出可下载Excel | 否，复用小龙虾现有文件能力 |
| L04 | 填写文件导入Skill | 接收已填写模板，固定程序读取数值，调用ERP预校验，展示变更，确认后调用批量写入 | 小龙虾对话中上传文件、确认预览、接收结果 | 否，与L03合为一个Skill的两个阶段 |
| L05 | 异常解释 | 根据程序返回结果说明缺失、重复、锁定、版本冲突及失败原因 | 草稿疑问、导入异常清单、处理结果 | 否，复用对应入口 |
| L06 | 核算问答 | 查询已有指标、解释利润变化及费用构成，链接来源；不由AI重新计算金额 | 先复用小龙虾对话；Web“问一下”可后续增加 | 本期不单独建设分析聊天页 |

首批核心是L01—L05，L06在统一指标接口稳定后接入，不阻塞基本核算及看板上线。

## 四、五类模板清单

共用一个“核算数据模板导入Skill”，不拆成五套独立系统。

| 模板 | ERP提供的预填信息 | 用户填写 | 正式数据归属 |
|---|---|---|---|
| 月固定人工成本 | 人员编号、姓名、角色、月份 | 月人工金额 | 人员＋月份，一人一月一条，不按项目重复展开 |
| 项目人员提成 | 项目编号/名称、人员编号/姓名、角色、归属月份 | 提成金额 | 项目＋人员＋月份 |
| 项目人员奖金 | 人员、月份及适用项目 | 奖金金额 | 人员＋月份，项目关联及费用映射需固化 |
| 项目异常费用 | 项目、分配月份、预计费用口径 | 当月预计金额 | 项目＋科目＋月份 |
| 项目固定成本分摊 | 项目、分配月份、预计费用口径 | 当月预计分摊金额 | 项目＋科目＋月份 |

流程：请求模板 → 小龙虾取数生成 → 下载填写金额 → 上传回小龙虾 → ERP预校验 → 确认差异 → ERP写入 → 返回批次结果。

空白表示不处理，0表示明确设为0；更新是覆盖为填写金额，不是再次追加。项目/人员/期间信息由模板批次和行标识定位，服务器重新校验权限。重复提交不重复入账，已结月份禁止直接覆盖。

## 五、ERP与小龙虾接口对接清单

以下为接口能力分组，实际端点和复用范围在开发盘点后确定。

| 接口能力 | 提供方 | 调用方 | 返回/处理内容 |
|---|---|---|---|
| 用户及授权范围 | ERP | 小龙虾 | 业务操作人、项目/人员及数据权限 |
| 模板基础数据 | ERP | 小龙虾 | 适用项目、人员、角色、月份、行标识、已有金额及版本 |
| 模板批次登记/查询 | ERP | 小龙虾 | 生成范围、模板版本、行范围及身份，支持后续核验 |
| 导入预校验 | ERP | 小龙虾 | 新增/更新/不处理/异常、原值与新值、锁定及预览版本 |
| 导入确认写入及结果查询 | ERP | 小龙虾 | 按确认预览执行幂等写入，返回批次及结果 |
| 工时材料解析 | 小龙虾侧适配服务 | ERP | 结构化草稿、来源定位、匹配候选、疑问项 |
| 工时查询/校验/写入 | ERP | ERP页面、小龙虾适配服务 | 已有记录、冲突、权限、版本和正式提交结果 |
| 核算指标及明细 | ERP | Web看板、小龙虾 | 同一口径的项目/人员数据及来源明细 |

工时提交由本人在ERP中确认；财务导入由授权人员在小龙虾中确认。工具服务账号不能替代业务操作人权限。

## 六、双方验收责任

| 场景 | ERP责任 | 小龙虾责任 |
|---|---|---|
| 材料缺日期/项目/时长 | 校验正式记录必填信息 | 明确标出疑问，不猜测填满 |
| 相同事项重复出现 | 检查已有记录及请求幂等 | 合并识别候选、展示冲突 |
| 模板项目/人员被改动 | 根据批次核验行身份及权限，拒绝越权 | 发现格式/结构变化并提示 |
| 金额变更 | 固定数值校验、版本检查、事务写入 | 明确展示原值、新值、差额，取得确认 |
| 月结锁定 | 强制执行锁定及反结账规则 | 调用接口前后说明锁定，不绕过限制 |
| 核算准确 | 统一固定计算、来源追溯、月度与累计一致 | 查询并解释结果，不另算一套数字 |

## 七、实施顺序与待收口事项

建议顺序：①盘点ERP数据及规则 → ②通用数据和接口 → ③五类导入Skill、双端日程 → ④固定核算和月结 → ⑤两个Web看板 → ⑥历史补齐、整体对算和试运行。具体工期需结合代码、接口现状及人员投入评估。

保留三项主要业务决策：项目所得税跨月处理、部分预计项目费用的默认分月方法、项目人员奖金的项目成本映射。其他角色规则不在本期提前实现。

历史范围：项目为2026年2月1日起立项项目；咨询师为2026年2月起参与的全部项目。历史工时允许按月估算补录，标记历史估算，与日常按日记录区分。
