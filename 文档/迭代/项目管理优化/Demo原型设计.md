## 1. 实现方案与边界

采用现有工作台内新增业务模块、共用一份数据状态及核算逻辑的前端交互方案。相比各页面各存一套静态数据，能够演示修改工时／费用后核算和看板联动；相比每页单独创建 iframe，符合现有每模块一个常驻 iframe 的状态保留方式。页面按职责拆分文件，避免把全部功能写在一个脚本中。

复用当前 HTML、CSS、JavaScript 技术及公共客户端，不新增后端服务或前端框架。根工作台登记新菜单与模块，业务代码位于 `原型/项目管理/项目管理优化/`。页面可独立打开，也可嵌入工作台；本地运行不依赖真实 ERP 或小龙虾服务。

金额实际计算，业务流程可编辑和保存。AI识别及龙虾对话编排采用模拟；五类财务模板实际生成.xlsx，用户在Excel填写后上传，由浏览器真实解析并校验。不连接真实AI、小龙虾或ERP生产接口。小龙虾演示通过独立的模拟对话场景体现，不在 ERP 业务页新增五类模板上传／下载功能。

## 2. 页面与导航

| 公共菜单 | 页面 | 主要交互 |
|---|---|---|
| 项目管理 → 我的项目日程 | Web 日／周／月日程，默认周视图 | 选择日期、项目、角色；时间段或小时数录入；新增、修改、复制日／周、多日草稿、批量提交；AI 草稿确认 |
| 项目管理 → 项目列表 | 最小项目列表及详情 | 项目／负责人／状态筛选，查看合同、交付收入及成员；详情内“核算设置”维护收入比例版本和预计费用 |
| 财务管理 → 核算工作台 | 核算数据、导入记录、月结三个页签 | 分类及期间查询、授权纠错、来源记录、批次详情、完整性检查、试算、月结及反结账 |
| 核算分析 → 项目分析 | 月度／累计指标、趋势和成本结构 | 筛选项目与期间，展示合同、交付收入、回款、成本、税前／税后利润、净利率及盈亏平衡回款；下钻及导出 |
| 核算分析 → 咨询师分析 | 人员月度指标及项目构成 | 收入、工资、提成、奖金、利润、饱和度、未分摊人工和盈亏平衡；趋势、下钻及导出 |
| 日程演示辅助入口 | 手机尺寸日程 | 默认当天，新增／修改工时、AI 草稿及确认提交，复用 Web 数据和校验；不展示核算看板 |

项目列表及详情只补齐核算设置所需的演示基础，不扩展完整立项、合同审批或项目生命周期系统。模拟小龙虾、演示身份切换和重置示例数据放在明确的演示辅助入口，与正常业务操作区分。

页面沿用系统现有按钮、筛选、表格、状态标签及弹窗交互。公共一级／二级菜单保持统一；二级选中为左侧红色竖线、浅红背景及红字。菜单切换同步高亮，业务页签可复用、关闭，未保存编辑须确认。

## 3. 数据、状态与核算

使用虚构项目、人员和跨月数据，覆盖正常盈利、跨月亏损回调、零收入、缺少输入、多项目投入及锁定月份；不复制原始工资或人员样例。

统一状态包含项目、成员及角色、考勤示例日历、工时草稿／正式记录、人员月工资／奖金、项目人员提成、实际费用、预计费用、收入比例版本、导入批次、修订记录与月结快照。业务数据共用稳定标识，来源抽屉展示同一份原始记录，派生人工分摊不另作原始成本重复写入。

浏览器本地保存演示数据，保留跨页面查询及未保存状态；支持确认后重置。存储不可用或保存失败须明确提示，不能显示为已保存；识别到版本变化时拒绝静默覆盖。Web 与手机预览复用同一业务状态和校验。

核心计算及校验遵循已确认决议：

- 工时 0.5 小时步进，同人跨项目／角色每日合计≤8 小时、当月合计≤考勤标准工时，非工作日禁止提交；考勤示例日历显式含工作日、休息日及调休情况。日常工时与历史月度估算分别存放，不伪造历史日期。
- 收入比例按月份生效，同项目同月合计≤100%。项目收入取确认交付收入，合同额按项目去重，回款和应收独立取数。
- 项目人工＝月固定人工÷月标准工时×项目工时；个人计整月人工，未投入部分不强行分摊。人员奖金仅计个人成本，项目年终奖分摊另行维护。
- 预计费用逐月手工填写，总额由月度汇总，不自动均分。
- 项目累计所得税＝MAX（累计税前利润，0）×15%，本月税额取累计差额，可为负；个人所得税仍按 MAX（月税前利润，0）×15%。
- 个人盈亏平衡点＝（固定人工＋提成＋奖金）÷［1－（税费＋管理费）÷当月交付金额］；取当月金额，不写死分母。项目盈亏平衡回款沿用需求中的累计公式。
- 金额使用统一精度与舍入口径，明细和汇总可核对；零收入、缺必要数据或分母非正分别提示原因，不用 0 隐藏缺失或错误。净利率、饱和度等汇总使用合计分子／合计分母，不平均百分比。

## 4. 可演示的主要链路

1. **工时影响核算**：切换本人身份 → 新增或 AI 生成草稿 → 补齐疑问 → 严格校验 → 提交生效 → 查看项目人工及咨询师饱和度变化。
2. **五类Excel录入**：纯对话输入期间及录入请求 → 龙虾直接回复一个含全部五类的.xlsx附件（人员固定成本／项目核算数据两个Sheet）→ Excel黄色列填数保存 → 对话选择文件并发送 → 校验身份/版本/数值 → 对话说明差异 → 回复“确认导入”后整本一次性写入，保留来源及各类批次 → ERP导入记录追溯。只提供文本输入、文件选择和发送；无生成按钮或类型/月份表单。演示重复提交、已结月及预览后版本冲突。
3. **项目核算设置**：财务选择项目 → 调整某月收入比例或预计费用 → 校验并保存 → 月度及累计看板联动，人员奖金与项目年终奖分别展示。
4. **月结与反结账**：财务检查缺失 → 试算并下钻 → 月结锁定 → 尝试修改显示锁定原因 → 填写原因反结账 → 修改、检查后续月份影响并重算 → 重新月结。后续依赖已结月不得静默覆盖。
5. **核算与对账**：在两个看板选择相同人员／项目／期间 → 查看来源及导出；项目跨月亏损显示所得税负数回调，个人盈亏平衡按用户公式计算。

身份切换用于演示角色可见范围：普通人员仅维护本人日程，财务及授权管理人员查看对应核算数据。前端身份切换不作为生产鉴权能力。

## 5. 公共组件影响与验证

接入现有 `ERPClient`、页签协议及公共版本标记，模块使用一个常驻 iframe；公共组件修改限定于新模块登记和必要的统一样式兼容，改动前检查预算及回单影响范围。预算和回单的业务逻辑、独立导出基线及已有默认标记不能被覆盖。

验证分三部分：

- 核算与状态测试：已确认所得税、奖金、费用分月、盈亏平衡及零分母；工时精度、跨项目日／月上限、调休日、草稿不计核算、锁定及版本冲突。
- 浏览器交互验证：各页面导航、筛选、编辑、保存、下钻、导出、AI／导入模拟、月结及反结账；1440／1024 宽度 Web 和约 390 宽度手机日程。
- 公共回归：预算、回单及新模块菜单高亮、折叠、页签复用／关闭、未保存确认、跨模块状态保留和统一版本标记。

测试结果、截图及操作手册保存在本迭代目录，临时运行输出放 `.cache/`。原型通过只表示本地交互和程序计算验证，不替代真实接口联调、服务端权限及财务样本账验收。
